# 剪纸方向：代码 demo 和 Lovart 示意图的对比（2026-10-22）

- 示意图：`lovart-field.jpg`（提示词 1 跑出来的现场画面）。
- 代码画的：`demo-region.jpg`（区域视图）、`demo-close.jpg`（近景）、`demo-island.jpg`（全岛）。
- 在线打开：`paper.html`（本地 `npm run dev` 后访问 `/paper.html`）。
  - 参数：`?seed=1&days=40&view=region|island|close`；
  - 按 1、2、3 切换视图，滚轮缩放，拖动平移。

## demo 做了什么

- **地形完全由推演的格子生成**（鸟岛，种子 1，推演 40 天）：
  - 离岸距离场分出深海、中海、浅海、浪花、海岸几层，草地和灌丛各用一层指示场；
  - 每层纸有低频扭曲（海岸线不跟着格子走）、带纤维毛刺的白色撕边，以及往右下方落的投影；
  - 草地和灌丛的颜色随植被量泛黄：被吃坏的地方会变成枯色纸。
- **贴纸按格子撒**：
  - 草丛来自 P1，被啃的地方换成稀疏草丛；
  - 灌丛来自 P2，植被量低时换成稀疏灌丛或枯枝；
  - 岩石、卵石、漂流木、海带来自 P3；
  - 投影由代码加：同一张图压扁、斜切、模糊。
- **代表单位**：
  - 每个物种按格子数量聚成几个代表，每格只归给最近的一个代表，所以数量签加起来正好等于总数；
  - 大小按体重的 0.12 次方压缩：鸟 2.6 格、鼠 3.0、兔 3.8、猫 4.3。
  - 动物用 P7 整只剪纸（2026-10-22 起）：每只代表从五个姿势里随机选一个；鸟一半趴在巢里，一半站在巢边。
  - 同一物种按站姿的剪纸面积统一缩放，避免长尾巴、长耳朵影响大小。
  - P7 缺失时退回代码画的占位木偶。
- **标记和界面**：P6 的笼子、三角、圆环、木桩加代码画的蓝绳，朱红警报配被毁的巢，界面底板是撕边纸条。
- **确定性**：同一个种子画两次，除了左上角的耗时文字，像素完全一样。

## 和示意图的差距

| 方面 | 现状 | 怎么补 |
| --- | --- | --- |

| 光 | 只有投影，没有整体光感 | 加一层整体调色（暖色暗角），以后纪录片的光也从这里来 |

## 素材处理

- 原图在 `raw/`（从聊天里拿到的 JPEG）。
- 两步，先切图、再打图集：
  1. `python3 -I scripts/art/slice_sheet.py <素材表> <临时目录>/<表名> [最大边长]`：
     按品红抠背景、去溢色，再按行列空隙切出每个素材，并写 manifest.json；
  2. `python3 -I scripts/art/pack_atlas.py <临时目录>/<表名> public/proto/paper/<表名>`：
     打成一张有损 WebP 图集加一份 PixiJS 的 Spritesheet JSON（帧名"行_列"，manifest 原样放在 meta.rows 里）。
  - 仓库里只留图集（`public/proto/paper/P*.webp`、`.json`），切出来的小图不提交，随时能从 `raw/` 重新生成。
  - 你上传 PNG 原图后，重新跑一遍即可。

### 试过、放弃了的

- **纸板台阶**（陆地分几层抬高、露出棕色侧面）：层间的厚度和缝隙示意图里没有，已删。
- **一片片叶子拼草丛、灌丛**：不够整体，也不是好的画法。
  - 只保留 P8 叶片铺地面（见下）；
  - 代码画的植物改成景观表现图的画法：细草叶束、分层剪影（`plants.ts`）。
  - 留作 `plants=code` 对照，默认不用。

### 现在的做法

- **地面**：
  - 草地和灌丛的地面去掉白边和投影，边缘柔和过渡。白色撕边只留在水陆之间。
  - 草地上铺两层：一层 P8 小叶（约兔子身长的四分之一，左上亮边、右下小影子），一层 P1 草皮贴片。
    - 都直接画进地形图，平躺在地上；
    - 只改明暗，颜色仍由推演决定。
  - 海滩上铺 P3 卵石堆。
- **植被轮廓只有一套**：同一张灌丛场（和地形绘制同样的扭曲、同样的门槛）同时决定两件事：
  - 树冠下的暗地面（往里收一点、和草地混一半）；
  - 灌丛摆在哪：按树冠的视觉中心判断，不按脚。
  - 灌丛密密地叠成一整片，轮廓就是植物本身的剪影。
- **植物**：草丛用 P1，灌丛用 P2 里圆而密的那些（压暗，叠成示意图里的深绿一团）。
  - **大小**按兔子身长定（量自示意图）：
    - 一丛草约和兔子一样长；
    - 一团灌丛约是兔子的 1.1–1.7 倍。
  - **草丛**成片长（低频噪声），被啃得越狠越稀、越黄。植被量低时：
    - 草丛换 P1 第 5 行（被啃过的）；
    - 灌丛换 P2 第 5、6 行。
  - **投影**：所有立牌的投影都倒向右下（光从左上来）。
- **海岸**：
  - 水边按低频噪声成堆地摆 P3 岩石，成了示意图里那种岩岸；
  - 靠草地的一侧用长地衣的石头；
  - 深一点的水里有海草，沙滩上零星有漂木和贝壳。
- **动物**：每个代表单位按数量放 1–4 只，姿势各不相同（示意图里一群兔子就是三四只）。
  - 数量签才是真数，单独立一块，永远在最上面。
  - 拉远成全岛地图时只留一只。
- **不挡信息**：挡在动物、数量签、标记、警报前面的植物和石头不摆。
- **镜头**（`camera.ts`）：
  - 全岛视图正俯视；
  - 区域视图倾斜约 30°（接近示意图的角度）；
  - 近景 50°。
  - 植物、动物、标记始终正对镜头，像 SketchUp 的"面向相机"组件；地面只在竖直方向压扁。
  - 所有坐标换算只走 `project`、`unprojectGround`、`anchor`。滚轮缩放时，鼠标下的那块地面不动。
- **整体调子**：屏幕四角偏暖压暗。

### 开销（种子 1，本机无头浏览器）

- **启动**：地形约 1.7 秒、铺叶约 1.0 秒、摆植物约 0.04 秒。都只在载入时做一次。
- **显存**：地形和植被贴图约 16 MB，不含 P 系列素材本身。
- **帧时间**：无头浏览器是软件渲染，测出来的帧间隔没有参考意义，要在真机上看。

### 和示意图还差的

- **示意图是一张画，这里是按推演数据摆出来的**：草丛、灌丛、岩石的位置和疏密跟着真实的地形和植被量走，构图不会和示意图一模一样。
- **海岸**：示意图的岩岸更高、更连续；这里只是成堆的岩石立牌，没有连续的崖壁。
- **水面**：示意图的海水有明显的笔触纹理，浪花是好几道厚的白色花边；这里用 P4 纸纹和撕边，浪花偏细。（第三版改成了多层纸雕，见下。）

- **动物和标记**：仍是 P7、P6 整张剪纸。
  - 示意图里的猫画成了老虎，这里按比例用的是家猫；
  - 鸟是 P7 的样子，嘴偏长。
- **遮挡**：所有立牌按脚的位置排前后，没有更细的遮挡。

## 第三版（2026-10-22）：纸雕式的多层地形

- **截图**：
  - `compare-v3.jpg` 自上而下：示意图、第二版区域视图、第三版区域视图、第三版全岛；
  - `demo-v3-region.jpg`、`demo-v3-close.jpg`、`demo-v3-island.jpg`。
- **思路**：把地形当成一件真能做出来的纸雕。每一层是一张单色的纸，按等深线剪出来，一层层叠起来。
  - 第二版的水只有 4 层，每层都有白色撕边；
  - 现在的水有 12 层，从远海的群青、钴蓝到近岸的青、浅绿松石，越近岸越浅。
- **层和层之间怎么分开**：
  - 不用白边。只靠两样：往右下落的一点短投影，加上切口处比本层亮一点的细边（像纸的切口受光）；
  - 白色只用在岸边：一道断断续续的碎浪花（分形噪声决定哪里有），加一道贴岸的浪花。
- **每层的轮廓各自起伏**：两张低频噪声按层号转个角度组合，层与层的边不是一圈圈平行线，越往外起伏越大。
- **陆地**：
  - 海滩分湿沙（偏暗）、干沙两层；
  - 草地内部按离岸距离再分三层很浅的明暗台阶，平铺，没有厚度和缝；
  - 植物、铺叶和第二版一样。
- **颜色**：每层的纸色由代码指定；纸纹取 P4 的相对明暗，乘到这个颜色上。所以换色不用换素材。
- **开关**：只在植物模式（默认）下用。`?mode=stickers` 仍是第一版的四层水，画面不变。
- **开销**：
  - 地形约 2.5–3 秒（第二版约 1.7 秒）；
  - 逐像素循环里，先找出最上面一张完全盖住这里的纸，下面的层不画；离得远的层整层跳过；
  - 所有层统一成同一种对象形状，避免属性读取变慢。

### 第三版还差的

- ~~水面的笔触~~、~~岛的外沿~~：第四版已处理，见下。
- **草地的明暗台阶**很淡，近看才看得出。第四版调深了一点；要更明显的话，需要让层数跟着植被量变，或者让地形有高度。现在推演里没有高度。

## 第四版（2026-10-22）：地图边缘、水面刷痕、镜头滑块

- **截图**：`demo-v4-island.jpg`、`demo-v4-region.jpg`、`demo-v4-rotated.jpg`（区域视图，俯仰 45°、旋转 30°）。
- **地图边缘**：
  - 水在靠近地图边的地方一层层沉到最深那层，和外面的底色接上，全岛视图里看不出地图的边；
  - 用平滑的 min 让层的轮廓圆滑地拐过去；
  - 只改画法，不改场：陆地不动，植物和动物的摆放仍按原来的场。
- **水面刷痕**：水里十二层和底色乘一层横向拉长的噪声（明暗 ±8%），像示意图海水的笔触。纸还是单色的，只是带纹理。
- **草地明暗台阶**：三层的明暗从 ±4–5% 调到 ±5–7%，投影 0.10 → 0.14。
- **镜头滑块**（右上角）：
  - **缩放**：0.3×–4×；
  - **俯仰**：0–60°。默认"自动"（跟着缩放，越近越斜）；一拖就变成手动，之后滚轮缩放不改俯仰；
  - **旋转**：±45°；
  - **复位按钮**：俯仰回到自动、旋转归零；
  - 拖滑块时，屏幕中心下的那块地面不动；滚轮缩放时，鼠标下的那块地面不动；
  - 按 1 / 2 / 3 切视图时，俯仰回到自动，旋转保留；
  - URL 参数 `pitch`、`yaw`（度）可以直接指定，截图用。
- **旋转的做法**：
  - 地面（地形图和地上的投影）先在自己的平面里转，再竖直压扁；
  - 立起来的纸片（植物、动物、标记、数量签）只换位置、按转过以后的远近排前后，仍然正对镜头，和 SketchUp 的"面向相机"组件一样；
  - 地形里烤进去的投影跟着地面一起转（光固定在世界里）。
- **为什么有限**：
  - 地面是一张预先画好的图，纸片是正对镜头的平面；
  - 转得太多、俯得太低，平贴的地面和立着的纸片就对不上了，投影的方向也会显得不对；
  - 所以旋转限在 ±45°，俯仰限在 60°。

## 性能（2026-10-22）：载入从二十多秒到几秒

- **素材打成图集**：原来 P1–P8 切成 200 多张 PNG，网页要发 229 个请求、下载 10.6 MB；
  现在每张素材表一张 WebP 图集，共 8 个图集请求、1.9 MB。同一张图集里的素材在 GPU 上能合批绘制。
  和原来的 PNG 并排看，看不出差别。
- **地形分条并行地画**：逐像素的地形和铺叶按行切成几条，交给几个 Web Worker 同时画（`painter.ts`、`painter.worker.ts`）。
  每个像素只看自己的坐标、叶子按同样的顺序画，所以拼回去和单线程逐像素相同（截图比对过）。
  本机 4 核：约 5.3 秒 → 约 2.1 秒；核越多越快。
- **投影烤成一张贴图**：地上的投影原来每帧都对整张地图重新模糊，现在摆好以后模糊一次、烤成半分辨率的贴图。
- **不再每帧重画**：画面是静止的，只在镜头或窗口变了的时候画一帧，省电，笔记本风扇不转。
- **本机无头浏览器**（种子 1，40 天推演，本机预览服务器）：
  - 推演约 1 秒；
  - 素材 5.1 秒 → 0.35 秒（在 Pages 上省得更多，原来 229 个请求要一个个从网上拿）；
  - 地形和铺叶 4.6 秒 → 约 2.2 秒；
  - 第一帧：无头浏览器用软件模拟 GPU，上传贴图、编译着色器要好几秒，改之前也一样；真机的 GPU 上应该只要几十毫秒，这里量不出来。
  - 页面左上的说明里有"看见画面"（从打开页面到第一帧画到屏幕上，毫秒）和"一帧"（连画 5 帧的平均），在真机上看这两个数。
