# 决策记录

这份文档是对设计讨论的提炼：哪些已经定了，哪些已经否决、为什么。设计细节以 `GDD.md` 为准；这里的作用是防止反复讨论已经关上的门。

## 已定

| 主题 | 决定 |
| --- | --- |
| 名字 | 《生生事务所》/ Patently Alive，保留。 |
| 核心 | 物种设计 + 生态推演 + 兽医干预。"专利事务所"是框架：真实动物是"现有技术"，可检索、授权、改进或被驳回。 |
| 尺度 | **群体尺度优先**，个体尺度（家庭委托）以后做。两个尺度共享同一个世界和同一套物种设计，只是两种镜头。 |
| 群体问题从个体开始 | 兽医解决群体问题也要先研究个体：捕捉 → 检查 → 化验/尸检 → 推断 → 干预。个体视图在阶段 1 出现，用于诊断，不是另一个游戏。 |
| 物种设计 | 本身不分个体和群体尺度；同一份设计在两个尺度都成立。 |
| 战役结构 | 预设世界 + 真实生态史改编的情景。解锁路线：管理员 → 引种者 → 设计师。第一个情景：野猫与鸟岛（参照新西兰 Predator Free 2050）。 |
| 平衡 | 没有万能钥匙：设计原因而不是效果；成本非线性；成功带来风险（密度依赖）；干预有反作用；引种不可撤销；多维评分。约束必须有世界内的理由，不加任意约束。主导策略 = bug，用补上真实代价来修，不用硬性禁令。 |
| 找漏洞 | 让 AI 扮玩家专门找捷径，加批量参数扫描。 |
| 世界规模 | 大地图（群岛/大陆/沙盒，WorldBox 量级），有人类用地（农田、城镇、道路）。缩放层级：全图 / 区域 / 地块 / 个体。 |
| 推演方式 | 远处按格子算数量，近处展开成个体，展开收拢守恒；采样 = 从格子里抽出个体。 |
| 知识来源 | 随游戏打包的结构化数据（PanTHERIA、AnAge、EltonTraits、COMBINE、AVONET、AmphiBIO；Wikidata CC0；Wikipedia CC BY-SA 需署名）。WikiVet 是 CC BY-NC-ND，不能改编。运行时不联网取事实。 |
| AI 的位置 | AI 不是核心。只负责文书润色、客户来信、纪录片旁白之类的表达层；不决定任何结果。MCP 以后接入，只能调用和玩家一样的操作接口。 |
| 美术 | 田野笔记，已锁定，不混搭（见 CLAUDE.md 的视觉语法）。 |
| 美术节奏 | 逐阶段引入（2026-10-13）：每个阶段接入本阶段用到的美术，占位也用田野笔记的配色和墨线，不再等到阶段 4 一次性替换。理由：纯灰盒试玩太费劲。 |
| 迭代顺序调整（2026-10-14） | 阶段 2 拆成 2A、2B：先做阶段 3 离不开的前置（2A：现有技术条目、相似度检索、投放操作），接着做阶段 3（设计台与专利），设计生物做得差不多再回来做 2B（档案馆补全、情景 2 和 3 等）。阶段 2 的关卡在 2B 结束时判断。理由：设计生物是整个游戏的核心，要尽快验证。 |
| 节奏（2026-10-14） | 保留实时时钟和倍速，加事件自动暂停（报告出来、工作完成、警报响、季度结束）和"跳到下一件事"，玩家不用盯着倍速找介入时机。不改成回合制。阶段 4 做。理由：阶段 1 试玩时 100 倍来不及操作，不知道何时该介入。 |
| 呈现（2026-10-14） | 模拟内部保持真实数量（远处格子、近处个体，铁律 2 不变），画面和面板降低信息密度。具体方案阶段 4 设计、试玩验证；初步方向：代表点（一个点代表一群，限制同屏点数）；默认只露目标物种的走势和最响的一处警报；曲线、日志、完整数字收进随手可翻的笔记本。理由：阶段 1 试玩时信息太多、点太密，注意力失去焦点。 |
| 阶段 3.5（2026-10-15） | 阶段 3 第 4 步之后插入阶段 3.5，见 `PHASE3_5.md`。理由：中途试玩发现任何部件组合都能活，只看环境。 |
| 身体可行性（2026-10-15） | 先做骨骼、消化与食性、繁殖三项检查，架构上能继续加（体温、循环……）并读气候。提示而不是禁止：不可行的身体照样能投放，在世界里按程度失败（跑不动 → 站不住、难产、营养不良），死因看得懂。检查确定、阈值是带依据的数据，只借真实生物学，不借《天地创造设计部》的设定。 |
| 塑形（2026-10-15） | a + b：功能性塑形 = 把体重分给骨骼、肌肉、消化道、心血管、脂肪，份额是可行性检查的输入；外观层不影响能力。手绘画布、像素等画法只在独立实验页里做对比原型，正式游戏仍只用田野笔记（不是重开"风格混搭"）。 |
| 植被（2026-10-15） | 植被不是一个统一的数，而是数据定义的多种植物类型：各有食物质量、筑巢、遮蔽的差别；能被吃坏（残留、根、土壤），恢复慢；和以后的气候相互影响。 |
| 气候（2026-10-15） | 以后一定会加，不只是气温，还有降雨、季节等更丰富的气候环境。现在的系统要留接口。 |
| 体重上限（2026-10-15） | 设计台的体重从 5 克到 100 吨（原来到 100 千克）。比拟合数据里最重的物种（陆生哺乳动物：森林象约 4.75 吨；鸟：鸵鸟约 111 千克）还重时，设计台提醒"这是外推"。默认骨骼分配下：约 3.6 吨起跑不动，约 15 吨起走不动，约 54 吨起站不住；更大的要多给骨头。 |
| 繁殖节奏（2026-10-15） | 大型动物几年才生一窝（按体重拟合的全年胎间隔超过一年时用它），不再规定每年至少一窝；设计台的仔数可以选"自动"，取同体型、同食性的典型值。食肉动物的体型不设硬上限：吃不饱饿死是推演里自然发生的事，第 6 步的食性检查只在设计台提醒。 |
| 繁殖的取舍（2026-10-15） | 玩家只选每窝几个和早成 / 晚成，不填新生体重。一窝总重由母亲的体重定（PanTHERIA 拟合，早成的重一些），新生体重 = 一窝总重 ÷ 仔数（Smith & Fretwell 1974 的"数量与大小"取舍）。比同体重真实新生儿的范围（1%–99% 分位）还小：幼崽保不住；还大：难产。鸟的蛋重只随体重，蛋数超过同体重真鸟的上限就养不活。泌乳不单独查（已经算在一窝总重里）。 |
| 审批流程（2026-10-15） | 不做得过于复杂：一半是形式（文书带来的幽默和彩蛋），一半是内容（保证游戏进行的必要约束）。只做案头审查（相当于 WHO 路径的第 1 阶段）：审查员看设计台的核算出结果，**不设试验田，不做分批投放**；身体撑得住就能通过，放进世界随便玩。理由：投放进世界本身就是玩法，流程太长会拖垮节奏；这是游戏，不是真的要放进自然界。`docs/research/` 里"试验田 = WHO 第 2 阶段""可逆性分级""分批开放"等映射作废，只留作背景。 |
| 调性 | 温馨、诙谐、一本正经地荒唐。幽默来自文书和客户，从不来自嘲弄动物。 |
| 技术 | 网页优先；模拟内核纯 TS 且确定；多人时服务器权威；存档即回放。 |
| 迭代 | 阶段 0 灰盒推演 → 1 野猫与鸟岛 → 2 档案馆与引种 → 3 设计台与专利 → 4 扩展与美术。每阶段有关卡标准，过了才往下走。开发快，试玩时间不压缩。 |

## 已否决（不要重新提议）

| 方向 | 为什么否决 |
| --- | --- |
| 美术风格混搭（像素、星露谷风、MC 风、复古 RPG、桌面微缩、专利铜版画、复古科普平涂等与田野笔记混用） | "什么都想要一定会是四不像的"。只用田野笔记。 |
| 海报式的概念图当界面 | 好看但不是游戏界面，没法交互。概念图以游戏截图为准。 |
| 小岛级别的小地图 | 太小，要大世界。 |
| "言出法随"、以 AI 生成为核心玩法 | 会变成换皮的 AI 工具。 |
| 把以前聊过的方向缝在一起（夏尔诊所、女巫药铺、裁缝、兽医史科技树等） | 强行缝合、牵强；兽医史科技树单薄。 |
| 照搬《天国餐馆》/ Heaven's Design Team 的概念和用词 | 只借"设计生物的事务所"这种气质，不抄设定。 |
| 用一个个体故事（比如猫逃出去）硬串起个体和群体尺度 | 牵强。改为两种尺度分开，共享世界和物种设计。 |
| 运行时让 AI 现场搜索事实 | 不可控。 |
| 用硬性、没有世界内理由的约束来防漏洞 | 改用真实代价。 |
| 罐头式、无脑重复的玩法 | 每个情景要有真实的生态问题和取舍。 |

## 仍然开放

- **以后的点子（2026-10-15，现在不做）**：玩家随手手绘一个动物 → 拓扑抽象 → 处理成标准的、可分配的参数（体重分配、部件）→ 把手绘和这些信息交给 AI，生成和 `handoff/002` 同尺寸、同画风的动物精灵，让设计的生物无缝进游戏。AI 只画外观，不决定能力（铁律 5、6）。

见 `GDD.md` 最后的"开放问题"，主要是：俯视二维还是等距 2.5 维、纪录片旁白是否配音、现有技术库首批收录哪些动物、参数（TNR 覆盖率、群体免疫阈值等）开发前再核对。
