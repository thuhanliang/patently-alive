# 路线图（2026-10-17 起，草案；2026-10-24 按玩具重排）

取代 `GDD.md`"迭代计划"里按系统切的阶段（0 → 4）、`PHASE2.md` 开头的"顺序调整"，以及阶段 3、3.5 的剩余步骤。
设计看 `GDD.md`（先看开头的"愿景校准"），数值看 `MODEL.md`，定了什么、否决了什么看 `DECISIONS.md`，**按什么顺序做看这里**。

## 为什么改

阶段 0–3.5 做了 50 多个 PR：推演、兽医、档案馆、设计台、身体可行性都有了。
但"委托 → 设计 → 审批 → 投放 → 推演 → 兽医 → 结算"这一局，到现在还没有一次从头到尾跑通过；试玩只能看到一个模拟计算程序，感受不到"游戏"。

原因：

1. 阶段按系统切，每个系统都能无限加真实度，于是一直在系统里打磨，不回到主循环。
2. 画面和交互推迟到最后，试玩无从判断"好不好玩"。
3. 临时的改动直接插进当前阶段，阶段越拉越长。

## 怎么推进

- **按可玩的里程碑切**：每个里程碑结束时，都有一个能从头玩到尾的版本，过关标准用一次试玩回答。
- **每个里程碑都接入它用到的画面和交互**，不等到最后。
- **真实度工作进"真实度待办"**，只有某个里程碑需要时才拉进来。原则是"内部贴近科学，呈现给玩家要简单"。
- **临时的想法和试玩反馈先进待办**，在里程碑结束时统一排序。只有改变核心方向的，才当场停下来改 GDD 和这份路线图。
- 不变的：CLAUDE.md 的铁律（确定性、守恒、内容即数据、指标只由引擎定义、能力只由性状推导、AI 不决定结果、统一操作接口），每个 PR 只做一件事。

## M0 · 表现验证（做完）

目标：在大规模实现之前，先定"看起来、摸起来、放出来"是什么样子。

最大的技术风险是**参数化生物**：玩家拼出来的动物，外形和动作都要好看、可控。纪录片的画面形式跟着生物的表现方式走，不先定 3D。V1、V2、V3 可以并行，V4 等 V3。V3 先做最便宜的一条路当对照；生物最终用哪种表现方式（2D 骨骼、2.5D 精灵、低多边形模板……），等 Lovart 第 1 轮的方向出来再定。

## M1 · 设计台玩具（现在）

目标：没有目标也愿意玩；改一处，代价当场长在身上。取代原 M1 第 2 步"体重分配滑块和体检栏"，并提前。独立页面 `desk.html`。

1. **纸偶骨架 v0**（只在渲染层；独立页面 `desk.html`，手感说明 `docs/feel/desk.md`）：
   - 四足兽模板，代码画的剪纸零件挂在骨头上，关节露出铆钉（`docs/research/creature-rig.md`）；
   - 站、走、跑、吃、趴五个姿态加插值；
   - 节奏用缩放律：步频随腿长，Froude 数决定走跑，呼吸随体重；尾巴、耳朵弹簧跟随；
   - 体型标尺：身后叠同体重的真实动物剪影，可以把猫拖成虎。
2. **桌面舞台和直接操作**：
   - 拖把手改体重、腿长、尾长；
   - 体重分配做成一块纸饼；
   - 部件托盘，拖上去"咔"地扣住；
   - 每一下改动约 1 秒的反应。
3. **代价长在身上**：
   - 可行性检查 → 跛、晃、吃了不长肉、母亲变瘦；
   - 冷、热、地形 → 喘、发抖；
   - X 光一层；
   - "一天的饭量"。
   - **做到这一步停下来，给用户和朋友试玩。**
4. **背面和文字**：
   - 规格书：公式代入数值；
   - 老同事的批注：数据驱动；
   - 愿望词典：数据驱动；
   - 能量小票。
5. **名字、传说、标本柜**：定格用静帧加运镜，可以和真动物合影。
6. **接回游戏**：取代现在的设计弹窗；投放进现场。

**过关**：试玩的人没有目标也玩了一阵子，试了好几种怪组合，说得出"它为什么跛"。

## M2 · 世界玩具

目标：玩家参与创作世界里的故事；动作几天内就有看得见的后果。

- 认领起名，家谱；导演只挑选、不制造事件。
- 伪装相机、相册，加上习惯化；GPS 项圈；标志重捕。
- 从世界里长出来的小目标；三级打断；"跳到下一件事"（原 M3 的节奏部分提前）。
- "要是你没来"的影子线；恢复分的基准改成"玩家到来以前"。
- 证据门控：死因不再免费，由尸检、相机、巢检挣来。
- 故事书 v0：静帧加运镜，字幕卡。
- 呈现减法：回到 DECISIONS"呈现"定的默认只露最要紧的东西。

**过关**：试玩的人说得出"我这周为什么派队去那儿""我是怎么发现的"。

## M3 · 诊台玩具

目标：兽医有细节、有手感，不是实验室模拟器。

- 体检手势：毛细血管再充盈、心率、体况评分、口腔。
- 化验台：McMaster 虫卵计数、血涂片、PCR 电泳。
- 鉴别诊断板。
- 尸检：推断死亡时间，从咬痕取 DNA。
- 治疗、复诊、收容康复放归；群体工作（疫苗诱饵、FAMACHA、耐药）。
- 用得到的疾病与寄生虫从原 M4 提前。
- 个案编辑器。

## M4 · 串成一局

原来的 M1（委托 → 设计 → 申请与检索 → 审查 → 投放 → 兽医 → 结算 → 事务所，场景切换）、M2（档案馆扩充、引种同流程、情景 2 和 3、召回改版）、M3（委托关卡序列、找主导策略、调平衡、沙盒）合在这里，用前三个玩具搭起来。

## M5 · 故事和分享

- 纪录片短片：从故事书里剪出来。
- 绘本导出；剧场模式；甲方模式。
- MCP：故事钩子，只用和玩家一样的操作接口。
- 场景做成能打印、粘贴的纸模型。
- 多人。

#### 原 M1 · 一局完整的设计循环

目标：不看说明，能从一张委托单一直玩到季度结算。每一步都可以很简陋，但必须首尾贯通，画面用 M0 选定的风格（占位也行）。

1. 委托单：一个鸟岛委托（目标、期限、预算）。
2. 设计台：加上体重分配滑块和体检栏（原阶段 3.5 第 9 步），从现有技术开始改。
3. 申请书与检索报告：自动生成，显示最像的现有技术（原阶段 3 第 5 步）。
4. 案头审查：给出三种结果之一（原阶段 3 第 6 步）。顺带定下"致命的身体是驳回，还是照样能放"。
5. 投放：进入全屏现场。
6. 推演和兽医售后：现有的兽医工具、个体视图、尸检。
7. 季度结算和客户回信，回到事务所。
8. 场景切换按 V2 的结论做，至少有事务所、设计台、现场三个场景。

**过关**：试玩的人不看说明玩完一局，能说出"我的动物为什么成 / 为什么败"。

#### 原 M2 · 现有技术即设计

目标：引种作为设计的一条捷径，进入同一条流程。

- 档案馆扩到约 40 条现有技术，配知识卡；翻卡、检索的交互和美术。
- 引种走和设计一样的检索、审查、投放流程。
- 第二、第三个情景（夏威夷獴、麦夸里岛兔和猫），各自需要的引擎补充（农田、栖息地偏好等）。
- 原阶段 3 的"2.0 版本"（召回改版）。

**过关**：引种能引出有趣的连锁反应；同一张委托，设计和引种各有道理。

#### 原 M3 · 战役

目标：一张张委托关卡串成战役，然后接沙盒和长期经营。

- 委托关卡序列：设计台部件、档案馆、兽医工具随进度逐步开放（取代原来"管理员 → 引种者 → 设计师"三个身份）。
- 批量推演和脚本玩家找主导策略、调平衡（原阶段 3 第 8–9 步）。
- 节奏：事件自动暂停、"跳到下一件事"；信息呈现：代表点、笔记本。
- 沙盒模式：一个自己的世界，长期经营。

**过关**：AI 找捷径和批量推演都找不到主导策略；试玩的人愿意自己再玩一遍。

#### 原 M4 · 纪录片正式版、疾病与寄生虫

- 纪录片按 V4 的路线做正式版：事件检测、剪辑语法、旁白、配乐、导出分享。导出格式、横竖屏、声音在线生成还是预先打包，到这里再定。
- 疾病与寄生虫（SIR、寄生虫生活史、疫苗、驱虫），以及对应的兽医工具。

之后：多人与 MCP。
