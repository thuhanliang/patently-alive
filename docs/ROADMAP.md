# 路线图（2026-10-17 起，草案）

取代 `GDD.md`"迭代计划"里按系统切的阶段（0 → 4）、`PHASE2.md` 开头的"顺序调整"，以及阶段 3、3.5 的剩余步骤。
设计看 `GDD.md`（先看开头的"愿景校准"），数值看 `MODEL.md`，定了什么、否决了什么看 `DECISIONS.md`，**按什么顺序做看这里**。

## 为什么改

阶段 0–3.5 做了 50 多个 PR：推演、兽医、档案馆、设计台、身体可行性都有了。
但"委托 → 设计 → 审批 → 投放 → 推演 → 兽医 → 结算"这一局，到现在还没有一次从头到尾跑通过；试玩只能看到一个模拟计算程序，感受不到"游戏"。

原因：

1. 阶段按系统切，每个系统都能无限加真实度，于是一直在系统里打磨，不回到主循环。
2. 画面和交互推迟到最后，试玩无从判断"好不好玩"。
3. 临时的改动直接插进当前阶段，阶段越拉越长。

## 怎么推进

- **按可玩的里程碑切**：每个里程碑结束时，都有一个能从头玩到尾的版本，过关标准用一次试玩回答。
- **每个里程碑都接入它用到的画面和交互**，不等到最后。
- **真实度工作进"真实度待办"**，只有某个里程碑需要时才拉进来。原则是"内部贴近科学，呈现给玩家要简单"。
- **临时的想法和试玩反馈先进待办**，在里程碑结束时统一排序。只有改变核心方向的，才当场停下来改 GDD 和这份路线图。
- 不变的：CLAUDE.md 的铁律（确定性、守恒、内容即数据、指标只由引擎定义、能力只由性状推导、AI 不决定结果、统一操作接口），每个 PR 只做一件事。

## M0 · 表现验证（现在）

目标：在大规模实现之前，先定"看起来、摸起来、放出来"是什么样子。三条线互不依赖，可以并行。

| 编号 | 做什么 | 谁做 | 产出 |
| --- | --- | --- | --- |
| V1 | 美术风格对比：四个画面（事务所、鸟岛全屏现场、设计台、纪录片一帧）× 几种风格（田野笔记 2D、2.5D 等距微缩、低多边形黏土白模、水彩绘本、自定） | 你跑图，我写提示词包 | `handoff/005-style-test.md` → 图和评分 |
| V2 | 场景流程原型：事务所 → 设计台 → 全屏现场 → 实验室 / 尸检 → 结算 → 回事务所，可以点着走一圈；现场对比 2D 俯视和 2.5D 等距两种投影 | 我 | 一个独立的原型页（Pages 上能打开），用占位画面，接真实推演但不接玩法细节 |
| V3 | 纪录片技术样片：从鸟岛的一段回放自动生成约 20 秒的短片（three.js 白模 / 黏土渲染、光照、景深、镜头路径；浏览器 TTS 读模板旁白；占位配乐；导出 webm） | 我 | 一条样片和一页结论：效果、开发量、浏览器性能、能否从确定性回放复现、在线 TTS 和音乐生成要不要接 |

V3 要先和你定的事：导出格式（浏览器直接录的 webm 在 iOS 和微信里不好分享，mp4 要多做一步封装）；横屏 16:9 还是竖屏 9:16；旁白和配乐是运行时在线生成，还是预先生成好打包（影响成本、隐私，以及能否从确定性回放复现）；AI 生成配乐能不能公开分享。另外 three.js 是 PixiJS 之外新加的依赖，CLAUDE.md 的技术栈要跟着改。

**过关**：选定一种美术风格和地图视角；定下场景列表和切换方式；纪录片的技术路线（要不要 3D、声音怎么来）有结论。结论写进 GDD 和 DECISIONS。

## M1 · 一局完整的设计循环

目标：不看说明，能从一张委托单一直玩到季度结算。每一步都可以很简陋，但必须首尾贯通，画面用 M0 选定的风格（占位也行）。

1. 委托单：一个鸟岛委托（目标、期限、预算）。
2. 设计台：加上体重分配滑块和体检栏（原阶段 3.5 第 9 步），从现有技术开始改。
3. 申请书与检索报告：自动生成，显示最像的现有技术（原阶段 3 第 5 步）。
4. 案头审查：给出三种结果之一（原阶段 3 第 6 步）。顺带定下"致命的身体是驳回，还是照样能放"。
5. 投放：进入全屏现场。
6. 推演和兽医售后：现有的兽医工具、个体视图、尸检。
7. 季度结算和客户回信，回到事务所。
8. 场景切换按 V2 的结论做，至少有事务所、设计台、现场三个场景。

**过关**：试玩的人不看说明玩完一局，能说出"我的动物为什么成 / 为什么败"。

## M2 · 现有技术即设计

目标：引种作为设计的一条捷径，进入同一条流程。

- 档案馆扩到约 40 条现有技术，配知识卡；翻卡、检索的交互和美术。
- 引种走和设计一样的检索、审查、投放流程。
- 第二、第三个情景（夏威夷獴、麦夸里岛兔和猫），各自需要的引擎补充（农田、栖息地偏好等）。
- 原阶段 3 的"2.0 版本"（召回改版）。

**过关**：引种能引出有趣的连锁反应；同一张委托，设计和引种各有道理。

## M3 · 战役

目标：一张张委托关卡串成战役，然后接沙盒和长期经营。

- 委托关卡序列：设计台部件、档案馆、兽医工具随进度逐步开放（取代原来"管理员 → 引种者 → 设计师"三个身份）。
- 批量推演和脚本玩家找主导策略、调平衡（原阶段 3 第 8–9 步）。
- 节奏：事件自动暂停、"跳到下一件事"；信息呈现：代表点、笔记本。
- 沙盒模式：一个自己的世界，长期经营。

**过关**：AI 找捷径和批量推演都找不到主导策略；试玩的人愿意自己再玩一遍。

## M4 · 纪录片正式版、疾病与寄生虫

- 纪录片按 V3 的技术路线做正式版：事件检测、剪辑语法、旁白、配乐、导出分享。
- 疾病与寄生虫（SIR、寄生虫生活史、疫苗、驱虫），以及对应的兽医工具。

之后：多人与 MCP。
