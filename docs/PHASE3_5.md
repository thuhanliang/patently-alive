# 阶段 3.5：身体可行性与植被

插在阶段 3 第 4 步（投放进鸟岛）和第 5 步（申请书）之间。依据：阶段 3 中途试玩的反馈和 `docs/research/` 下的调研。

顺序：2A → 阶段 3 第 1–4 步 → **3.5** → 阶段 3 第 5–9 步 → 2B。

## 目标

阶段 3 中途试玩发现：**任何部件组合都能造出来、投放出去，能不能活只看环境**。真实的身体有自己的极限，
体型太大骨骼撑不住、肠子太短消化不了粗草、一窝生太多母亲撑不住。这一阶段补上这一层，同时让植被成为真正会被吃坏、
有多种类型的东西。

三条线：

1. **身体可行性**：先做**骨骼、消化与食性、繁殖**三项检查；架构上是可以继续加检查的登记表，
   以后加体温、循环、飞行曲线等，并且能读气候（不只是气温：降雨、季节，以及更丰富的世界气候）。
2. **塑形**："a + b"。
   - (b) **功能性塑形**：把体重分给骨骼、肌肉、消化道、心血管、脂肪，默认值取真实比例，这些份额就是可行性检查的输入。
   - (a) **外观**：不影响能力。这一阶段只在独立的实验页里试几种画法（田野笔记、手绘画布、像素），**只做对比，不进游戏**。
3. **植被**：从"一层草 + 一层灌丛"改成**数据定义的多种植物类型**，各有食物质量、筑巢、遮蔽的差别；
   能被**吃坏**（啃不到的残留、根储备、土壤），恢复慢。

## 关卡标准

- 不合理的设计**看得出来为什么不行**：设计台的老同事提醒说出原因，投放后尸检写出新死因（承重骨折、难产、营养不良）。
- 合理的设计不受影响：17 条现有技术（真实动物）全部通过三项检查。
- 兔子多的地方，植被和掩护真的会变薄、很久长不回来，"兔子啃光植被、鸟失去掩护"这半个转折在鸟岛上看得出来。
- 鸟岛几条路线（`npm run routes`）仍然各有优劣，没有出现新的主导策略。
- 确定性、守恒测试一直绿。

## 设计原则（本阶段的硬约束）

1. **提示，而不是禁止**（GDD 设计台一节）。不可行的身体照样能造、能投放，在世界里**按程度失败**：
   跑不动 → 走不动 → 站不住；难产；长期营养不良。不加"设计台拒绝"。
2. **能力只由性状推导**（铁律 5）。检查只看体重、部件、体重分配，算出的是"这具身体的特性"（例如"最低能消化的食物质量"），
   和世界无关；推演里再拿它和这个世界的植物比。所以同一份设计在不同情景里结果不同，但设计本身和它的 id 不变。
3. **确定、不掷骰子**（铁律 1）。检查是纯函数；新的死亡只在风险大于 0 时才抽随机数，真实物种的随机数流不动。
4. **阈值是数据**（铁律 3）：写在 `src/data/scaling/viability.json`，每个数带"依据三级"（数据 / 规律 / 假设）、置信度和出处，
   和 `MODEL.md` 一致。拟合得出的（新生体重等）走 `npm run data:fit`。
5. **默认什么都不变**：没写体重分配的设计 id 不变；真实物种不带新字段；植被重构先做到逐位一致，再单独打开"吃坏"。
6. **复杂度预算**：每个体重份额最多影响 3 个指标；检查的种类由引擎定义，数据不能新增检查。

## 范围

### 身体可行性

- **检查登记表**（`src/sim/viability.ts`）：每项检查读设计、部件、体重、缩放结果、体重分配，
  输出等级（正常 / 吃力 / 不行 / 致命）、余量、对推演的影响、能量开销、老同事的提醒。
  检查声明自己需要什么输入（身体 / 食物 / 气候），需要的输入还没有时跳过，这就是以后接气候的接口。
- **骨骼**：安全系数随体重下降（平方–立方定律），站姿（腿型）抵消一部分；两足动物另算伸肌比例。
  安全系数 < 1.5 跑不动（追捕和逃跑打折）；< 1 走不动、有骨折风险；更低站不住，多数早夭。
- **消化与食性**：消化道容量 ∝ M^1.06、需求 ∝ M^0.75（Jarman–Bell），算出"这副消化道最低能靠什么质量的食物过活"；
  挑食的嘴（啃种子的门齿、食籽喙）能挑出更好的部分。食虫动物超过约 21.5 千克、食肉动物超过约 1 吨吃不饱。
- **繁殖**（2026-10-15 定，见 `DECISIONS.md`）：一窝总重由母亲的体重定，玩家选的仔数把它分开；
  新生儿比同体重真实范围小就保不住，大就难产。鸟比蛋数。泌乳已经算在一窝总重里，不单独查。
- **新死因**：营养不良、承重骨折、难产。进死因账本、尸检报告、死因面板。
- 体温、循环、飞行连续曲线**本阶段不做**，但架构要留好位置。

### 塑形

- **体重分配**：骨骼、肌肉、消化道、心血管、脂肪五个份额，玩家调倍数（0.5–2 倍），此消彼长；部件给默认值和上下限
  （奔跑腿多给肌肉、后肠发酵多给消化道、翅膀限制消化道和脂肪）。
  每个份额影响的指标：
  - 骨骼：安全系数、骨折风险；
  - 肌肉：移动、追捕、能量；
  - 消化道：最低食物质量、能量；
  - 心血管：每日活动上限、能量；
  - 脂肪：断粮能撑几天、能量（有了气候后加保温）。
- **设计台**：五个滑块；"体检"栏用和推演同一套数算出头一年会因骨折、难产、营养不良损失多少；线稿跟着份额变（骨头重腿就粗）。
- **外观实验页**（`lab.html`，只在开发时打开，不进正式构建）：同一份设计用几种画法画出来比较：田野笔记、手绘画布、像素。
  按 `DECISIONS.md`，正式游戏仍然只有田野笔记；实验页只是给你比较、找手感。

### 植被

- **植物类型写成数据**：每种有生长、季节、在哪种地形上长、食物质量（整体和可挑选部分）、每天最多被啃多少、
  虫子产量、给筑巢的掩护。鸟岛先用"草本 + 灌丛"两种，重构后结果和现在逐位一致。
- **能被吃坏**：
  - 啃不到的残留：体型小、贴地啃的动物能啃得更低（按体型推导，不另写数据）；
  - 根储备：一天被啃掉一半以上根就停长，少于四成慢慢补回（Crider）；
  - 土壤：长期裸露就退化，长得更差，恢复要很多年。
- **给气候留接口**：每天的生长输入集中到一处（现在是季节和天气，以后加降雨、气温）。
- 然后在鸟岛和小鸟岛上打开"吃坏"，重新调平衡，写进 `MODEL.md`。

## 美术

需求清单见 `handoff/004-body-and-plant-art.md`：
- 现有每个部件的完整线稿，大小两个尺度；
- 体内系统剖面层（体重分配的五个系统各三档，消化道按部件画）；
- 新死因的尸检插图；
- 植物类型和"茂盛 / 被啃 / 裸地 / 退化"四种状态；
- 后续部件（颈、耳、眼、角、防御……）；
- 实验页用的风格对比参照。

素材没到之前，用代码画的田野笔记占位：蓝图线稿已经是代码画的，剖面层和植被状态也先用代码画。

## 不做

- 体温、循环、飞行连续曲线、气候本身（以后一定会加，见上面的接口）。
- 试验田：已取消（`DECISIONS.md` 审批流程）。可行性只在设计台给"体检"预估，后果在世界里发生。
- 审批流程：保持轻量，一半是形式（文书的幽默），一半是内容（必要的约束）。本阶段只保证检查结果能给第 5–7 步的审查意见引用。
- 正式游戏里的新画风。
- 手绘 → 拓扑抽象 → 标准参数 → AI 生成精灵（记在 `DECISIONS.md` "仍然开放"，以后再说）。

## 建议顺序（每步一个 PR）

1. 检查登记表、体重分配（默认值）、`viability.json`；只出提醒，不影响推演
2. 死因账本加"营养不良、承重骨折、难产"，尸检和死因面板跟着改（还没有新死亡）
3. 骨骼检查接进推演（追捕、移动、骨折）
4. 繁殖检查（一窝总重与新生体重的真实范围；鸟比蛋数）
5. 植被重构成多种植物类型（逐位一致，不改行为）
6. 消化与食性检查（按植物类型的食物质量）、营养不良
7. 植被能被吃坏（残留、根、土壤），默认关闭
8. 鸟岛、小鸟岛打开"吃坏"，重新调平衡 → **发试玩版本**
9. 设计台：体重分配滑块、体检栏、线稿跟着变
10. 外观实验页（第 1 步之后任何时候都可以并行做）

每一步都要：17 条现有技术全部通过；真实物种的推演和 `npm run routes` 的输出不变（第 8 步除外，第 8 步专门调平衡）。
