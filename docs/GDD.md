# 生生事务所 · 游戏设计文档

Oct 13, 2026 · @Viktor

## 一页纸概述

《生生事务所》（暂名，英文暂名 Patently Alive）是一款物种设计与生态推演游戏：你经营一家温馨的小型生物设计与专利事务所，为客户设计物种、申请专利、投放到星球上，再作为售后兽医照顾它们。

**一句话**：设计一种动物，看世界怎么“验收”它，再用兽医的手段收拾它留下的烂摊子。

**四根支柱**

1. 设计即手艺：拼装身体、取舍代价，每个选择都在成品上看得见。
2. 真实生物学就是规则：反刍、气囊、免疫、寄生虫生活史都是机制，不是科普弹窗。
3. 两个时间尺度：设计台改图纸（慢、永久），售后兽医箱救现场（快、有代价）。
4. 世界会讲故事：推演自动剪成纪录片，失败也值得看。

**调性**：温馨、诙谐、一本正经地荒唐。幽默来自文书和客户，从不来自嘲弄动物。

**和同类游戏的差异**

| 同类常见问题 | 代表作 | 本作的解法 |
| --- | --- | --- |
| 看不懂物种为什么死 | The Sapling、Species: ALRE | 尸检报告和审查意见，把死因翻译成可读的文书 |
| 投放后只能旁观或扔陨石 | Equilinox、WorldBox | 售后兽医箱：TNR、疫苗、驱虫、隔离等有代价的中间层干预 |
| 没有性格与幽默 | 多数演化模拟 | 事务所、客户来信、专利文书、纪录片旁白 |
| 玩两小时就开始重复 | The Sapling、Niche | 委托、情景、多人和“现有技术”收集提供长期目标 |

## 世界观与设定

在这个世界里，物种是可以申请专利的产品；生生事务所是一家只有几张绘图桌的小工作室，靠为“星球业主”设计物种过日子。

### 世界

- 宇宙里有许多待开发的星球。业主买下一颗星球后，需要物种让它活起来。
- 专利局负责审查新物种。地球上已有的一切生物都被视为“现有技术”，收藏在自然档案馆里。
- 没有神，没有天界。设计物种是一门手艺，也是一门小生意。

### 事务所（玩家的家，也是主菜单）

- **绘图桌**：进入设计台。
- **档案柜**：已授权专利、发明库、客户档案。
- **标本柜**：每个授权物种的模型，点开看它在世界里的履历。
- **电话与信箱**：委托、保修电话、审查意见都从这里来。
- **放映室**：纪录片片库。
- **窗外的试验田**：小型测试环境，新设计先在这里跑。
- **事务所的猫**：只负责被摸、占桌子，偶尔压在申请书上。

工作室可以随进度慢慢布置，墙上会挂上专利证书和客户寄来的照片。

### 角色

| 角色 | 是谁 | 怎么出场 |
| --- | --- | --- |
| 主人公（玩家） | 事务所合伙人，形象可定制 | 在工作室里走动；多人时每人一个 |
| 审查员 | 专利局一位从不露面的审查员 | 只以审查意见通知书出场，语气永远庄重 |
| 档案馆员 | 自然档案馆的管理员 | 检索报告的署名人，偶尔在页边写一句私人批注 |
| 客户们 | 星球业主 | 来信、电话、验收评价 |

### 客户样例

- **退休宇航员**：想要一颗安静的花园星球养老，“别太吵，别太多腿”。
- **八岁的小业主**：要求宠物“永远不会死”。
- **矿业公司**：需要能吃掉铁锈的生物，预算充足，耐心很少。
- **主题公园老板**：要一只吉祥物，“可爱，但要让游客愿意排队”。
- **过敏的猫奴**：想要一只不会让自己打喷嚏的猫（完整样例见后文）。
- **一位植物学家**：只想要一种能给她的兰花授粉的东西，别的都不要。

## 核心循环

一次循环是：接委托、设计、检索与审查、投放、推演，再由兽医箱或设计台处理推演中暴露的问题。

```
接委托 → 设计 → 检索与审查 → 投放 → 推演
                                      │
     ┌────────────────────────────────┤
     │ 回路 A（快）：兽医箱干预 → 回到推演      （当季见效，要反复投入）
     │ 回路 B（慢）：设计台召回改版 → 回到设计  （几代后见效，效果永久）
     └─ 纪录片：从推演回放自动生成，不影响任何结果
```

两条回路是游戏的核心张力：兽医箱当季见效，但要反复投入；设计台召回改版要几代后才见效，但效果永久。纪录片从推演回放中自动生成，不影响任何结果。

### 一局的节奏

- **几分钟**：调一个性状、派一次兽医队、读一份尸检报告。
- **一个游戏季度**：完成一份委托，或熬过一次疫情。
- **一个游戏年**：经营一颗星球的生态，收集现有技术，充实专利目录。

## 尺度：先做群体，再做个体

游戏只有一个世界，但有两个镜头：群体视图推演一片生态，个体视图让你抓住其中一只仔细检查。物种设计不分尺度。先做以群体为主的星球委托；以一只动物的一生为主的家庭委托放到后面，复用同一个个体视图。

### 为什么分开

真实兽医学本来就分两条路：**个体医学**（伴侣动物诊所，病人是“这一只”）和**群体医学**（牧场、野生动物与公共卫生，病人是“一群”或“一个生态”）。TNR、口服疫苗诱饵、驱虫避难所属于群体医学；体检、训练、牙科、老年照护属于个体医学。把两者硬串成一个故事（先订一只，后来繁殖成灾）反而牵强。

### 群体问题从个体开始

真实的群体医学也从个体入手：抓几只做检查、采样、化验，对死亡个体做尸检，确诊之后才决定整群怎么干预。所以群体尺度里内置一个个体视图：

1. **发现**：群体视图里出现异常，比如某个区域死亡增多、种群曲线下滑。
2. **捕捉与检查**：派兽医队抓几只，进入个体视图：体温、体况评分、牙龈、粪便、血样。
3. **化验与尸检**：样本送实验室，尸体送尸检，得到病原、寄生虫负荷和死因。
4. **推断**：把几只个体的结果推到整个种群。抽样越多越可靠，抽样偏了结论也会偏。
5. **干预与复查**：TNR、疫苗、驱虫、隔离；之后回到第 1 步看效果。

这套个体视图在群体尺度里先做。以后做家庭委托时直接复用，只是加上主人、日常生活和衰老。

### 两种尺度对照

|  | 群体尺度（先做） | 个体尺度（后做） |
| --- | --- | --- |
| 委托 | 星球委托：业主、牧场主、保护区管理员 | 家庭委托：想要一只伙伴的人 |
| 交付物 | 一个物种投放到一片生态 | 一只或几只动物 |
| 舞台 | 一颗星球，数百到数千只动物 | 客户的家，一个小空间 |
| 时间尺度 | 季节、世代 | 一只动物的一生 |
| 推演什么 | 种群、食物网、疫病、迁徙、遗传 | 行为、健康、衰老、和主人的关系 |
| 兽医怎么出场 | TNR、疫苗诱饵、驱虫、隔离、栖息地管理 | 体检、就诊、行为训练、老年照护 |
| 满意度 | 生态稳定、物种存续、业主目标 | 陪伴指标、主人生活的改善 |
| 纪录片 | 一个物种的兴衰 | 一只动物的传记 |
| 引擎侧重 | 模拟规模大，美术需求小 | 个体内容多，动画与文案需求大 |

### 共享与整合

物种设计本身不分尺度：一份设计就是一套构造和性状，放进生态里是一个种群，放进客户家里是一只伙伴。

- **共享**：设计台、部件与性状、专利与现有技术库、发明库。在一种尺度里解锁的发明，另一种尺度也能用。知识在两种尺度之间流动，故事不需要流动。
- **同一份设计，两种读法**：群体尺度读取生态属性、传染病和遗传；个体尺度读取伴侣属性和临床疾病（牙病、肥胖、毛球、关节、泌尿系统问题）。
- **以后的桥**：一个家庭委托的设计被许多家庭采用，就成了一个“品种”。品种的基因库窄，几代之后会出现整个品种的遗传病，问题自然从“这一只”升级到“这一个品种”，进入群体尺度。真实的纯种猫狗正是这样。这座桥放到后续阶段。

## 设计台系统

设计台是游戏的手艺中心：玩家用模块拼出一个物种，系统实时算出它的代价和后果，并自动生成专利申请书。

### 身体模块（看得见、可拼装）

- **躯干与骨架**：体型、比例、四肢数量。
- **头部**：口器、眼、耳、角。
- **运动**：腿型、蹄或爪、鳍、翼。
- **体表**：毛、羽、鳞、裸皮，以及厚度和颜色。
- **尾**：平衡、游泳、储存脂肪或纯粹好看。

### 性状（看不见，但决定命运）

| 系统 | 可选项示例 | 代价与取舍 |
| --- | --- | --- |
| 消化 | 单胃、反刍、后肠发酵、纯食肉 | 反刍能吃粗草但慢；食肉效率高但依赖猎物 |
| 体温 | 恒温、变温 | 恒温不受天气限制，但要多吃很多 |
| 呼吸 | 肺、气囊、鳃 | 气囊供氧强，适合飞行和高海拔，结构更复杂 |
| 感官 | 视觉、嗅觉、听觉、回声定位、热感应 | 每种感官都耗能 |
| 繁殖 | 窝仔数、妊娠期、育幼投入、季节性繁殖 | 生得多就育得少 |
| 社会性 | 独居、小群、大群 | 群居能防天敌，但传染病传得快 |
| 免疫投入 | 低、中、高 | 免疫高少生病，但长得慢、生得少 |
| 防御 | 角、刺、毒腺、伪装、速度 | 毒腺要原料，角要钙，速度要能量 |

### 能量收支

每个物种都有一条收支线：维持身体 + 体温 + 活动 + 繁殖 + 免疫，必须小于等于能吃到的能量。超支的设计不会被禁止，只会在世界里饿死。设计台始终显示这条收支线。

### 推导属性

系统根据模块和性状算出：日均能量需求、散热能力、最高速度、寿命、繁殖率、各类疾病易感性。表面积与体积之比、体温调节、代谢率等真实规律都在这里起作用。

### 提示，而不是禁止

设计台从不说“不行”，只像一位老同事那样提醒：“这只动物的脖子有 3 米长，心脏需要很高的血压才能把血送到脑部。”要不要冒险，由玩家决定。

### 版本

每个物种都有版本号。投放后发现问题，可以发布 2.0 版。旧版本仍留在世界里，新旧版本会共存、杂交或竞争。

## 认知与行为模块

物种除了身体，还有一组认知与行为性状：它决定动物能不能陪伴人、能学会什么，也带来真实的代价。陪伴类委托是一大类需求，靠这个模块支撑。

### 指标

| 指标 | 含义 | 主要影响 |
| --- | --- | --- |
| 问题解决 | 摆弄物件、解开简单机关的能力 | 觅食效率、训练上限 |
| 玩耍与好奇 | 主动探索和玩耍的倾向 | 陪伴评分、无聊风险 |
| 社会依附 | 对同伴或主人的依恋程度 | 陪伴评分、分离焦虑 |
| 可训练性 | 学会新行为的速度 | 行为训练效率 |
| 专注时长 | 一次互动能维持多久 | 陪伴评分 |

这些指标由相对脑容量、社会结构和发育期长短推导，不能单独调高。

### 聪明的代价

- **大脑很贵**：脑组织耗能高。聪明的物种要吃更多、发育期更长、生得更少。
- **聪明会无聊**：刺激不够时出现刻板行为，比如鹦鹉缺乏刺激时会拔自己的羽毛；也可能破坏周围环境。需要“环境丰容”来缓解。
- **长寿也是需求的一部分**：伙伴可能比主人活得久。给一位老人设计长寿伙伴时，审查员会在意见书里礼貌地提一句。

### 行为训练（兽医箱新工具）

用正强化塑造行为：动物不是理解了规则，而是学会了“做这个动作会有奖励”。学会的行为按难度分级，每一级需要时间，也需要足够的可训练性：

1. **习惯**：固定时间出现在固定地点。
2. **简单动作**：推、拉、按、取。
3. **按提示操作**：例如提示出现时点某个格子。
4. **理解抽象规则**：做不到。档案馆会说明最接近的现有技术。

训练也用于医疗配合：让动物主动配合体检和打针，降低应激。

### 陪伴指标

陪伴类委托按世界里的实测打分：每日出现率、互动次数、专注时长、主人独处时间的减少。不按“学会了什么技能”打分。

## 专利与现有技术系统

每次设计都是一份专利申请；地球上真实存在的动物是“现有技术”，它们既是审查的对照，也是科技树的来源。

### 申请书（由设计自动生成，玩家可以润色）

- **说明书附图**：蓝图线稿，自动标注部件。
- **权利要求书**：每个关键性状一条，用工程法律腔书写。例：“权利要求 1：一种通过四室胃反复咀嚼以分解纤维素的装置。”
- **有益效果**：根据委托目标预填，玩家可改。
- **实施例**：设计者手记，可以留空，也可以写成日记。

### 检索：自然档案馆

提交后，档案馆把设计与“现有技术库”比对。现有技术库是一组真实动物条目，每条记录关键性状和几条准确的真实知识。相似度高的条目出现在检索报告里。

### 三种结果

| 结果 | 触发条件 | 玩家得到什么 |
| --- | --- | --- |
| 授权许可 | 关键性状与某种真实动物实质相同 | 这项“自然发明”收入发明库，以后可以直接使用；附一张真实知识卡 |
| 创造性改进 | 在现有技术上做出有效的新组合 | 一项属于事务所的新专利，进入专利目录 |
| 驳回 | 物种在测试中活不下来，或与申请内容不符 | 一封审查意见通知书，指出问题在哪 |

驳回不是惩罚，而是一封写得很认真的反馈信。

### 实质审查：试验田测试

授权前，物种要在试验田跑一段测试。审查员根据测试数据写审查意见，例如：“申请人声称该物种适应寒冷气候，但测试期间全部个体于第一个冬季死亡。”

### 发明库就是科技树

- 按“自然专利分类”组织：运动、摄食、呼吸、体温、感官、防御、繁殖、免疫、共生。
- 解锁来源：检索授权、完成委托、在纪录片里观察到的现象、售后处理过的病例。
- 发明之间有前置关系，例如“反刍胃”需要先解锁“消化道共生菌”。

### 专利目录

所有授权物种的作品集。每个物种有证书、版本历史、世界履历，以及它出演过的纪录片。

## 世界推演系统

世界是一颗持续运行的二维星球：环境决定资源，资源决定种群，种群密度决定疾病，所有结果都由确定的规则算出。

### 环境

- 生物群系：草原、森林、冻原、湿地、海岸、沙漠。
- 季节、温度、降水，以及水源分布。
- 植物层按覆盖度计算，不逐株模拟。

### 动物：近处是个体，远处是数量

镜头拉近时，动物是一只只个体，记录年龄、性别、能量、体温、健康、感染状态、寄生虫负荷和免疫，会觅食、躲避、交配、育幼、迁移。镜头拉远时，按格子记录每个物种的数量。详见本节末尾的「分层推演」。

### 食物网

谁吃谁由性状推导（体型、食性、防御、速度），不手工配置。食物网图显示每一条能量流。

### 疾病与寄生虫

- **传染病**：按易感、感染、康复分组（SIR 模型）计算。传播取决于接触频率，群居和高密度会加速传播。
- **跨物种传播**：亲缘或性状相近的物种之间可以传病，带出“一体健康”（One Health）问题。
- **寄生虫**：有完整生活史（宿主、环境阶段、中间宿主），并带有抗药性基因频率。
- **设计缺陷病**：由构造直接导致的问题，例如体型过大导致散热不良、脖子过长导致循环问题。

### 演化（可选开关）

默认关闭随机突变，保证设计意图清楚；沙盒中可以打开。打开后，抗药性、毛色、体型等会随选择压力变化。

### 事件

- 季节事件：旱季、寒潮。
- 随机事件：洪水、火山、外来物种漂流登陆。
- 客户事件：业主要在星球上修度假村，或带来一批宠物。

### 可观测性

种群曲线、食物网图、密度与感染热力图、个体档案、死因统计。时间可以暂停，也可以 1 倍、10 倍、100 倍速运行；报告出来、工作完成、警报响、季度结束时自动暂停，也可以一键"跳到下一件事"（阶段 4 做）。画面不 1:1 画出每只动物：一个点代表一群，默认只露最要紧的走势和警报，完整数据收进笔记本。

### 世界尺度

- 情景有大有小：教学关可以是一座小岛，后面是群岛、一整片大陆、有山脉和河流的大地图。例如新西兰式的完整情景是“主岛加一串离岸岛”：离岸岛可以清空入侵者作为避难所，主岛大到无法一次清完，只能分区推进。
- 沙盒生成多块大陆、多种生物群系和气候带，尺度对标 WorldBox。
- 地图上有人的痕迹：农场、城镇、道路。宠物和家畜从这里来，人兽共患病也从这里来。
- 大地图带来的玩法：入侵有推进的前线，疫病沿河谷蔓延，山脉成为屏障，兽医队要在地区之间调度，路程本身就是成本。

### 缩放层级

| 层级 | 看到什么 | 玩家做什么 |
| --- | --- | --- |
| 全图 | 生物群系、物种分布、疫病热力图、迁徙流向 | 宏观决策、调度兽医队 |
| 区域 | 动物以群落图标显示，围栏和防线 | 部署干预、划定隔离区 |
| 地块 | 一只只动物 | 放陷阱、投诱饵、选中个体 |
| 个体 | 捕捉后的检查画面 | 体检、采样、尸检 |

### 分层推演

一张大地图上可能有几十万只动物，不可能每只都单独模拟：

- **远处按格子算数量**：地图划成网格，每格记录每个物种的数量、感染数和寄生虫负荷，按繁殖、捕食、扩散、传播的规则逐格更新。
- **近处才是个体**：镜头拉近到地块层级时，把格子里的数量展开成个体在地图上活动；拉远时再收拢回数量。两种表示必须守恒，展开和收拢不能凭空多出或少掉动物。
- **抽样就是从格子里取个体**：捕捉检查的个体从格子里抽出，检查结果反过来修正玩家对这一格的认识，正好对应「群体问题从个体开始」。

这是模拟内核的基本结构，阶段 0 的灰盒就按这个方式搭。

## 售后服务部：兽医箱

物种交付后由事务所负责售后：客户报修时，玩家派兽医队到现场，用真实的兽医手段干预种群。

### 资源

每次干预消耗预算、人手（兽医队数量）和时间。客户满意度是第四种资源，扑杀之类的手段会拉低它。

### 工具

| 工具 | 做什么 | 真实依据与机制 | 代价或副作用 |
| --- | --- | --- | --- |
| 体检与采样 | 抽查一部分个体 | 粪便虫卵计数、血检；样本越多结论越可靠 | 花时间，会惊扰动物 |
| 尸检 | 为死亡个体出具死因报告 | 解决“看不懂为什么死”；报告指向设计或环境问题 | 需要找到新鲜尸体 |
| 绝育 / TNR | 捕捉、绝育、放归 | 研究常引用约 75% 的绝育覆盖率，种群才会持续下降；外来个体迁入会抵消效果 | 人手密集；覆盖不足几乎等于白做 |
| 注射疫苗 | 给个体接种 | 接种比例超过群体免疫阈值（1 − 1/R0）后疫情消退 | 需要捕捉，成本高 |
| 口服疫苗诱饵 | 空投诱饵 | 欧洲曾用这种方法清除西欧和中欧的狐狸狂犬病；诱饵口味决定谁来吃 | 非目标物种会抢食 |
| 驱虫 | 给个体驱虫 | “避难所”原则：全群驱虫会加速抗药性；只治最需要的个体，药效更持久 | 用多了药会失效 |
| 抗生素 | 治疗细菌感染 | 滥用产生耐药菌株，耐药基因可在世界中扩散 | 同上 |
| 隔离与移动限制 | 圈定区域，阻止进出 | 切断传播链 | 阻断迁徙，影响觅食 |
| 扑杀 | 移除感染或过量个体 | 见效最快 | 客户满意度大降；会被纪录片记录 |
| 迁地保护 | 把个体移到别处 | 保住濒危种群 | 可能把病一起带过去 |
| 营养补充 | 投放盐砖、矿物、饲料 | 纠正缺乏症 | 会让动物聚集，增加接触 |
| 栖息地管理 | 调整水源间距，修廊道或围栏 | 改变接触率和迁徙路线 | 见效慢，影响全局 |
| 生物防治 | 引入天敌或寄生物 | 有效但收不回来；真实历史上有引入后失控的例子 | 风险最高 |
| 行为训练 | 用正强化塑造行为 | 动物学会的是“做这个动作有奖励”，不是理解规则；也用于让动物配合体检和打针 | 耗时间；可训练性低的物种学得慢 |

### 两个时间尺度

|  | 设计台 | 兽医箱 |
| --- | --- | --- |
| 速度 | 慢，几代之后见效 | 快，当季见效 |
| 持久性 | 永久 | 需要反复投入 |
| 成本 | 研发与审查 | 预算、人手、满意度 |

每次危机都要求玩家判断：现场救急，召回改版，还是两样都做。

### 保修电话与召回

- **保修电话**：客户报告问题，附一张模糊的照片和一段不太准确的描述。诊断从这里开始。
- **召回**：发布新版本后，可以逐步替换旧版本，也可以用绝育让旧版本自然退场。

## 平衡：没有万能钥匙

平衡不靠禁令，而靠真实的约束：每种能力都由性状推导，每个性状都有代价，每种干预都有反作用。一条约束如果在世界里讲不出理由，就不该存在。

### 原则

1. \*\*只能设计原因，不能声明效果。\*\*玩家不能写“只吃老鼠”，只能设计体型、活动时间、捕猎方式；谁被吃由这些性状推导。能抓住老鼠的东西，通常也抓得住体型相近、同一时段活动的雏鸟。最典型的“万能钥匙”就这样被生物学本身关上了。
2. \*\*代价随强度非线性上升。\*\*体型、代谢、大脑、免疫、毒腺都耗能，而且越往极端越贵。把一项能力堆到顶，会在别处付出更大的代价。
3. \*\*太成功本身就是风险。\*\*任何过于成功的物种都会改变环境：吃光食物、因聚集而传病、成为新捕食者或寄生虫的目标。密度越高，这些反作用越强。
4. \*\*干预都有反作用。\*\*驱虫会产生抗药性，诱饵会被非目标物种吃掉，扑杀会拉低满意度，引入的天敌收不回来。
5. \*\*引入不可逆。\*\*投放的物种不能一键删除，只能用兽医工具和生态手段减少它。每一次引种都要想清楚。
6. \*\*评价是多维的。\*\*单一指标拉满不等于赢：目标同时看恢复、稳定、多样性、成本和福利。

### 合理约束与任意约束

- 合理：来自生物学（能量收支、体型缩放）、来自客户（“本岛禁止引入哺乳动物”是业主的规定，写在委托里）、来自预算和人手。
- 不做：没有世界内理由的限制，比如“每关只能投放一次”“这个性状禁止使用”。

### 怎么找漏洞

- **让 AI 当玩家找捷径**：通过 MCP 让 Claude 在各个情景里反复尝试“最优解”，记录它找到的策略。
- **批量推演扫参数**：在每个情景里自动跑大量参数组合，看有没有一种策略在几乎所有情景里都赢。
- **主导策略就是漏洞**：一旦某个策略在多数情景里都是最优，回到第 1 至 3 条原则，找出是哪条代价没有被模拟到，补上真实的代价，而不是加一条禁令。

## 游戏模式

三种单人模式共用同一套系统，区别只在目标从哪里来。

### 委托模式

客户来信提出需求，需求里藏着生物学约束。委托分两种：星球委托（群体尺度，先做）和家庭委托（个体尺度，后做），见「尺度」一节。交付后客户按满意度打分，满意度带来预算和新客户。委托可以串成客户的长期故事，比如宇航员的花园星球一年年扩建。

### 自由沙盒

一颗属于自己的星球，所有已解锁发明可用，可以打开演化突变。没有目标，只有世界。

### 情景挑战

情景挑战是群体尺度的主体：走进一个已经出了问题的预设世界去解决它。详见「情景战役」一节。

## 情景战役：预设世界与解锁路线

群体尺度的主体不是从零造物，而是走进一个已经出了问题的世界，用兽医工具、引种和设计去解决它。从零创造是最开放的沙盒模式。

### 预设世界

每个情景是一片预设生态：地形与气候、一组预设物种（本地种和外来种）、一段已经发生的“历史”，以及业主的目标。预设物种都来自现有技术库，数值由性状数据库校准。

### 解锁路线：三个身份

| 阶段 | 玩家能做什么 | 学到什么 |
| --- | --- | --- |
| 管理员 | 只用兽医工具管理现有物种 | 种群、传播、干预的代价 |
| 引种者 | 从档案馆引入真实物种 | 食物网与连锁反应 |
| 设计师 | 在设计台创造新物种 | 取舍与创造性改进 |

解锁来自完成情景、档案馆授权，以及在推演中观察到的现象。设计台是最后才完全打开的能力，而不是起点。

### 情景库（改编自真实生态史）

| 情景 | 真实原型 | 核心问题 | 玩家会撞上的转折 |
| --- | --- | --- | --- |
| 野猫与鸟岛 | 新西兰把野猫列入 Predator Free 2050 清除目标 | 野猫捕食本地鸟类、蝙蝠、蜥蜴 | 只除掉猫，被压制的其他入侵者会反弹 |
| 兔子、猫与苔原 | 澳大利亚麦夸里岛 | 病毒控兔后猫改吃海鸟；清除猫后兔子回升，植被被啃光 | 只清除一种入侵者，可能比不动更糟 |
| 甘蔗田的獴 | 夏威夷 1883 年引入獴 | 引入獴控制甘蔗田的鼠害 | 獴不待在你放它的地方，去吃地面筑巢的鸟 |
| 流浪猫街区 | 城市 TNR | 绝育覆盖率不足时数量不降 | 迁入个体抵消效果 |
| 狐狸与狂犬病 | 欧洲口服疫苗诱饵 | 用诱饵清除疫情 | 别的动物抢诱饵 |
| 牧场蠕虫 | 驱虫抗药性 | 控虫同时保住药效 | 全群驱虫会毁掉药 |

每个情景都附一张档案馆的“历史卡”。例如夏威夷那张会更正一个流行说法：常听到的版本是獴白天活动、老鼠晚上活动，所以控鼠失败；夏威夷毕晓普博物馆的资料则说，獴其实是相当好的甘蔗田捕鼠者，问题在于它离开甘蔗田，跑进别的低地和山林去捕食地面筑巢的鸟和鸟蛋。

### 情景走法：野猫与鸟岛

1. **开局**：一座岛，本地鸟在减少。岛上有野猫、老鼠和兔子，历史卡说明它们都是外来的。
2. **管理员阶段**：玩家用诱捕和尸检锁定野猫，集中清除。鸟回升了一季。
3. **转折**：没了猫，老鼠和兔子数量上升。老鼠吃鸟蛋，兔子啃光植被，鸟失去筑巢的掩护，又开始减少。尸检报告从“被捕食”变成了“巢失败”。
4. **引种者阶段**：玩家想引入天敌控鼠。档案馆列出候选，并附上夏威夷獴的历史卡。选错了，就是下一个情景。
5. **可行的路线不止一条**：同时处理多个入侵者；先控鼠再控猫；用围栏保护繁殖区；分阶段推进。纪录片会记录你选的那条路。

### 评价

多维评分：目标物种恢复、生态稳定度、物种多样性、花费、动物福利。没有唯一的正确答案。

## 需求系统

每个委托背后有四层需求；交付会一层层暴露它们，玩家用有限的访谈去挖出真实动机。同一句话，动机不同，正确答案就不同。

### 四层需求

| 层 | 客户会说吗 | 例子：不掉毛的猫 |
| --- | --- | --- |
| 显性需求 | 直接写在信里 | 不掉毛 |
| 隐性偏好 | 不说，交付错了才会不满 | 要毛茸茸，最好是长毛 |
| 真实动机 | 藏得最深，决定正确答案 | 过敏？黑沙发上全是白毛？不想打扫？ |
| 底线 | 只有踩到才知道 | 不能有异味，不能天天梳毛 |

### 需求递进

追加需求不是剧本写死的，而是交付暴露了下一层：

1. 交付无毛猫：显性满足，隐性失败。回信：“它摸起来像一个温热的橡皮球。我想要毛茸茸的。”
2. 设计“长毛但完全不掉毛”：毛发有生长、退化、休止三个周期，不脱落的毛会困在毛被里打结；或者毛持续生长，必须定期修剪。试验田里出现毛结、皮炎和夏季过热。
3. 客户回信：“我没时间每周梳毛。”玩家这才回头去问：你到底为什么怕掉毛？

同一句“不掉毛”，动机不同，解法完全不同：

- **过敏**：掉毛不是关键，要降低过敏原分泌。
- **黑沙发上一层白毛**：把猫设计成黑色。审查员在意见书里只写一句：“申请人的技术方案出人意料地有效。”
- **不想打扫**：削弱换毛的季节高峰。真实知识：常年开灯的室内猫换毛会失去季节节律。
- **有时最好的方案是不设计新物种**：建议客户换一种梳毛方式、调整家里的光照。游戏奖励这种诚实的咨询。

### 访谈

访谈就是兽医的病史采集：主人描述往往不准，好兽医靠问对问题。

- 每个委托 **3 次**提问。
- 线索也藏在别处：来信的措辞、客户寄来的照片、提到的时间细节。
- **公平规则**：每个隐藏动机至少有两条可发现的线索。失败后回头看能恍然大悟，而不是觉得被系统耍了。

### 需求单与四种落点

任何一句愿望都由 AI 翻译成一张结构化的需求单，玩家确认或修改。AI 只翻译目标，不判定结果。需求单上的每一项都落到四种地方之一，系统从不回答“听不懂”：

| 落点 | 例子 | 系统怎么回应 |
| --- | --- | --- |
| 构造可实现 | 掉毛少的猫 | 映射为指标目标值，直接开始设计 |
| 需要解锁的发明 | 会发光的猫 | 档案馆列出萤火虫、深海鱼等现有技术，获得授权后可用 |
| 外观层 | 粉色的，像云朵 | 永远可以，不影响能力 |
| 超出生物学 | 永远不会死 | 给出最接近的真实替代：裸鼹鼠（能活三十多年的啮齿动物）、灯塔水母（能逆转回幼体阶段） |

### 拆解做不到的愿望：宇航员想要“陪我下棋的东西”

动物不可能学会下国际象棋，游戏也不假装它能。处理方法分四步：拆动作、找能做的、挖动机、诚实说明做不到的部分。

档案馆的回信：

> 经检索，现有技术中最接近的是“会下井字棋的鸡”。 需要说明的是，该鸡并不理解井字棋。它是在按一台电脑给出的提示啄对应的格子，所以它从没输过。 国际象棋暂无现有技术。

拆开之后：

| 下棋里包含的东西 | 动物能做到吗 |
| --- | --- |
| 理解规则、计算棋步 | 不能 |
| 每晚准时坐到棋盘对面 | 能：习惯与依附 |
| 专注地看着你、回应你的动作 | 能：社会性与专注 |
| 用嘴或爪子推动棋子 | 能：好奇心与操作能力 |
| 按提示点某个格子 | 能，但要训练 |

访谈挖出的动机：他在空间站上每晚和一位同事下一盘棋，退休后晚上变得很安静。他要的不是对手，是每晚都出现在棋盘对面的伙伴。最好的交付是一种好奇、爱摆弄小物件、喜欢固定作息、依恋主人的动物：每晚八点跳上桌子，盯着棋盘，偶尔推倒一个兵。满意度按陪伴指标计算。

### 打分

- 客户满意度按世界里实测的指标计算，不看申请书怎么写。
- 动物福利是独立的审查轴：比如寒冷星球上的无毛猫、为了“可爱”把脸设计得过扁导致呼吸困难。客户满意和福利评分是两条分数，不能互相抵消。

### 多人“甲方模式”

一人抽一张隐藏动机卡写委托，另一人当设计师，用 3 次提问去挖。两人轮流出题。

## 多人模式

两人或更多人作为事务所合伙人，在同一个世界或相邻的世界里一起玩；所有人看到的是同一份推演结果。

### 合作：同一颗星球

共享预算和发明库，按物种分工，例如一人负责植食者，一人负责捕食者。目标一致，但天然有张力：你的狼会吃掉我的鹿。

### 对抗：两块大陆

各自经营一块大陆，陆桥周期性开放。物种会迁徙、入侵、把病带过去。胜负按生态稳定度、物种多样性或客户评分计算。

### 异步：物种交换

把自己的物种“寄”到对方的星球，看它能不能在别人的生态里活下来。

### 专利玩法

- **交叉许可**：把自己的发明授权给对方，换取对方的发明。
- **联合申请**：两人一起设计的物种，证书上写两个名字。
- **侵权函**：你的物种跑进了对方的大陆，审查员会寄来一封措辞客气的函件。纯属展示，不影响胜负，可以关闭。

### 节奏

推演以服务器时间为准。可以设置“所有人确认后才快进”，避免一人加速打断另一人的操作。

## 自然纪录片系统

世界推演会被自动剪成纪录片：系统找出有故事的时刻，在回放中运镜，配上字幕和一位庄重的旁白。

### 原理

模拟是确定性的：记下随机种子和所有玩家操作，就能完整回放任何一段历史。纪录片是对回放的拍摄，不改变任何结果。

### 事件检测

系统持续扫描种群曲线和事件日志，标记这些时刻：

- **第一次**：首次捕食、首次繁殖、首次越冬。
- **剧变**：种群暴涨、崩溃、疫情暴发、灭绝。
- **转折**：天敌出现、入侵者登陆、干预生效、复苏。
- **个体故事**：某只个体活得特别久、走得特别远，或带着族群熬过危机。

每个事件有一个“故事分”，按分数挑选入片。本质上是对种群时间序列做异常检测，再把异常归因到事件。

### 剪辑语法

固定几种镜头：远景建立、跟拍个体、俯瞰迁徙、曲线叠在画面上、前后对比、慢放关键瞬间。每部片子按开场、发展、转折、结尾排列镜头。

### 旁白

AI 根据事件日志写旁白稿，只讲述已发生的事。语气庄重、克制，与画面里的狼狈形成反差。可以只有字幕，也可以配语音。

### 片种

| 片种 | 时长 | 何时生成 |
| --- | --- | --- |
| 季度纪录片 | 1 至 2 分钟 | 每个游戏季度结束 |
| 物种传记 | 1 至 3 分钟 | 物种灭绝时，或玩家手动生成 |
| 灾难特辑 | 约 1 分钟 | 重大疫情或灾害之后 |
| 年度回顾 | 3 至 5 分钟 | 每个游戏年结束 |

所有影片存进放映室，可以导出视频分享。

## 主人公形象定制与外观层

玩家可以用 AI 为自己的主人公生成一整套形象；物种外观也用同一思路，但外观只改变样子，不改变任何能力。

### 主人公

- 输入一段描述或上传参考图，生成一套统一风格的形象：立绘、工作中、思考、开心、沮丧、走路循环。
- 生成结果必须符合美术规范（同一套轮廓、线条和配色约束），所有玩家站在一起也不违和。
- 多人时每位合伙人有自己的形象，出现在工作室、证书署名和纪录片片尾。

### 物种的两层

- **构造层**：模块与性状，决定一切能力。
- **外观层**：颜色、花纹、细节装饰。可以手动调，也可以由 AI 按描述生成皮肤。

AI 画得再威风，模拟也只认构造层。

## AI 与 MCP：职责边界

AI 只负责出题、写文案和画外观；所有结果都由模拟计算，AI 没有任何玩家没有的权限。

### 游戏内的 AI 职责

| 职责 | 内容 | 能否影响结果 |
| --- | --- | --- |
| 委托生成 | 写客户来信 | 否：生物学约束来自固定的需求模板 |
| 文书润色 | 审查意见、检索报告、尸检报告的文字 | 否：数据由模拟给出 |
| 纪录片旁白 | 根据事件日志写旁白 | 否 |
| 形象与外观 | 主人公形象、物种皮肤 | 否 |
| 事件文案 | 为事件写新闻和来电 | 否：事件由规则触发 |

### MCP 接口

游戏对外提供一个 MCP 服务，工具与玩家操作一一对应：

- **读取**：世界状态、种群数据、尸检报告、发明库、委托。
- **设计**：提交设计，只接受已解锁的模块和合法参数。
- **操作**：投放物种、使用兽医工具（照常扣预算和人手）、调整时间速度。
- **生成**：请求一部纪录片。

这样 Claude 或 ChatGPT 能在对话里帮玩家构思委托、讨论设计、提交方案；多人模式里，它还可以作为第三位合伙人。

### 红线

- AI 不计算任何结果，也不能绕过预算和人手。
- AI 生成的图像只能用作外观层。
- 所有 MCP 操作都写进操作日志，可以回放。

## 知识系统与能力边界

档案馆不是一部百科全书：数字来自公开科研数据库，规律写进引擎，故事在开发时生成并人工审核。游戏运行时，AI 不提供任何事实，也不联网检索。

### 三种知识

| 种类 | 来源 | 用途 | 控制方式 |
| --- | --- | --- | --- |
| 数字 | PanTHERIA、AnAge、EltonTraits、COMBINE、AVONET、AmphiBIO 等性状数据库 | 现有技术条目的数据档案、相似度检索、校准引擎 | 下载固定版本，随内容包发布 |
| 规律 | 由上述数据拟合的公式，如代谢率随体重的缩放 | 让任意设计都能算出合理数值 | 写在引擎里，配单元测试 |
| 故事 | 维基百科（CC BY-SA）、维基数据（CC0）起草 | 知识卡，以及审查意见里的真实知识 | 开发时生成，必须带出处，人工审核 |

专业兽医资料只作参考阅读，不改编文字。WikiVet 当前授权禁止演绎，默克兽医手册同理。事实可以用，原文不能搬。

### 规模

知识卡按“发明”组织，每项发明配 2 至 4 个代表物种。第一版约 40 张，完整版一两百张。

### 运行时规则

- 不联网检索。
- 档案馆未收录的东西，在已收录条目里按性状相似度找最近的，回复“暂无收录，最接近的现有技术是……”。结果确定、可复现。
- AI 只把已有事实改写成审查员或档案馆员的口吻，不新增事实。

### 分层与扩展

| 层 | 内容 | 怎么扩展 |
| --- | --- | --- |
| 引擎层 | 模拟规则、公式、指标定义 | 只能通过引擎更新 |
| 规则数据层 | 部件、性状、发明、疾病、兽医工具 | 数据包 |
| 知识层 | 现有技术条目、知识卡 | 数据包 |
| 内容层 | 客户、委托、情景、事件 | 数据包 |
| 表现层 | 美术、文案风格、旁白音色 | 皮肤包 |

### 边界规则

- \*\*系统只认识它能计算的东西。\*\*指标是游戏的词汇表：愿望编译成指标，满意度按指标实测，所以指标只能由引擎定义。
- 数据包新增的性状，必须声明影响哪些已有指标、通过哪个公式钩子。校验器检查格式、单位、出处和能量收支。
- 需要全新机制的扩展是 DLC：一个新引擎模块加一批数据。方向举例：海洋包（浮力、鳃、水压）、古生物包（灭绝动物作为现有技术）、微生物包、家畜包。
- 指标有定义、有公式、有依赖关系，本质上就是一张指标知识图谱，可以按指标体系的方法管理。

### 复杂度预算（完整第一版）

| 项目 | 上限 |
| --- | --- |
| 指标 | 约 30 个（含认知与行为 5 个） |
| 部件与性状 | 约 40 个，每个最多影响 3 个指标 |
| 发明 | 约 40 项 |
| 兽医工具 | 7 种（含行为训练） |
| 每个委托的访谈提问 | 3 次 |
| 星球 | 1 颗 |

任何新东西加进来之前，必须说清楚三件事：它影响哪几个指标，玩家在哪里看得见它，它会怎么让人失败。说不清楚的，先不加。

## 调性与文案规范

游戏的幽默来自文书的一本正经和客户的天真，从不来自嘲弄动物或玩家。

### 幽默规则

1. 用正式文体写荒唐的事：专利、审查意见、检索报告严格遵守公文格式。
2. 客户可以天真，但不愚蠢；他们的需求总有合理的动机。
3. 审查员从不讽刺，只陈述事实；笑点在事实本身。
4. 每份文书最多一个笑点，其余都是真实信息。
5. 真实知识必须准确，幽默不能以牺牲准确为代价。

### 死亡与疾病

- 死亡是生态的一部分，画面上温和处理：个体倒下、淡出，留下一个小标记。
- 尸检报告用临床语言，不写血腥细节。
- 扑杀等手段如实呈现后果，但不渲染。
- 纪录片旁白对灭绝保持尊重。

### 用词

- 不用“神”“造物主”“天界”这类词。
- 事务所内部用工作室的日常口吻，对外文书用正式口吻。

## 完整样例：低掉毛家猫（家庭委托 · 个体尺度）

这个样例走完一次完整循环：委托、设计、检索、审查、交付、售后、纪录片。它也示范每份文书的口吻。

### 1. 委托信

> 您好。我是一名猫奴，也是一名过敏患者。我想要一只不掉毛的猫，这样我就不会打喷嚏了。希望它摸起来还是软软的。预算有限，但我的爱是无限的。 ——K 女士，一颗小型海岛星球的业主

### 2. 设计 1.0

玩家选择家猫骨架，把体表从“短毛”换成“裸皮”，保留胡须。设计台提示：“裸皮体表散热快，这只猫在冬天需要更多能量，或者一个温暖的窝。”

### 3. 检索报告

> 经检索，申请的设计与现有技术“无毛猫（斯芬克斯猫）”实质相同。 现予授权许可，“裸皮体表”已收入贵所发明库。 附：知识卡一张。 ——自然档案馆

**知识卡**：猫最主要的过敏原是一种叫 Fel d 1 的蛋白，主要来自皮脂腺和唾液，猫舔毛时把它涂满全身。掉毛只是把过敏原带到了家里各处。无毛猫同样分泌这种蛋白。

页边有一行档案馆员的手写批注：“很多人都这么想过。”

### 4. 审查意见通知书

> 申请人在“有益效果”中称：主人将不再过敏。 经审查，该效果缺乏依据。过敏原的来源是皮脂与唾液，与是否掉毛无直接关系。 另据试验田测试：裸皮个体在冬季能量消耗显著升高，夏季出现晒伤，皮脂在皮肤表面堆积。 请申请人修改有益效果，或提出新的技术方案。

### 5. 设计 2.0：一项创造性改进

玩家回到设计台，换回保暖的短毛，并使用发明库里的“分泌腺调控”，降低 Fel d 1 的分泌量。这在现有技术里没有完全相同的条目，于是获得一项新专利：“低致敏短毛家猫”。

### 6. 售后：它在 K 女士家的一生

交付之后，个体视图跟着这只猫走完一生，兽医以定期体检和就诊的方式出场：

- **第一次体检**：体重、牙龈、疫苗。
- **第一个春天**：换毛高峰，K 女士学会了每周梳一次毛。
- **第三年**：体重超标。行为训练加一个漏食球，让它吃得慢一点。
- **第十年**：关节变硬，跳不上窗台了。K 女士在窗台下放了一级台阶。

满意度按陪伴指标和福利评分计算。

### 7. 纪录片片段

> 她已经跳不上那扇窗了。但每天下午三点，她仍会沿着台阶，一级一级走上去，在阳光里躺下。 K 女士说，这是她养过最好的猫。审查员对此没有异议。

## 美术方向：田野笔记（已定）

整个游戏只有一种风格：一位博物学家的田野笔记本。所有画面都是这本笔记里的一页。不混搭其他风格。

### 视觉语法

| 元素 | 画法 | 含义 |
| --- | --- | --- |
| 自然 | 淡水彩、低对比、略降饱和 | 地形、植被、水，世界本身 |
| 动物 | 粗墨线描边、平涂、每个物种一个固定主色 | 世界里活着的东西 |
| 玩家的干预 | 蓝图蓝墨迹 | 围栏、陷阱、诱饵、路线、隔离线、选中框，像在野外地图上做的批注 |
| 警示 | 朱红 | 生病、死亡、入侵前线、危险，以及文书上的印章 |

### 色彩与材质

- 主色：奶白纸色、墨黑、蓝图蓝、朱红，外加一组低饱和的水彩自然色。
- 一种纸纹，一套线宽。
- 物种主色贯穿地图、图标和图表：鸟白身黑帽（图表用炭黑），兔沙色，鼠蓝灰，野猫橘色与黑白。

### 各画面

| 画面 | 画法 |
| --- | --- |
| 地块层级 | 淡水彩地图、墨线动物精灵、蓝图批注和界面 |
| 全图层级 | 一页手绘博物地图集：等高线、墨线河流海岸、物种分布色块、群落图标、迁徙箭头 |
| 工作室 | 同样的水彩加墨线插画 |
| 文书 | 奶白纸上的蓝图线稿，加一枚朱红印章 |
| 纪录片 | 同一套地图和精灵，加镜头运动、调色和黑边 |

### 克制规则

- 每种干预一个独特形状：陷阱方形、诱饵三角、采样点圆圈，围栏和隔离线是线。
- 批注默认只显示与当前工具或图层有关的部分，其余通过图层开关查看，一次只开一个数据图层。
- 警示只在一个地方大声：一条朱红横幅，日志里只记一行。
- 判断标准：新画面能不能被解释成同一本笔记里的一页。不能的，改到能为止。

### 已放弃的方向

桌面布景、专利铜版画、复古平涂、像素等候选全部不用，避免混搭成四不像。

### 待验证

同屏数百只动物的可读性，AI 概念图验证不了，在阶段 0、1 的原型里用真实精灵测试。已生成的地块层级和全图层级截图作为目标参照，可以直接贴在本节。

## 技术架构建议（理想形态）

推荐网页优先、服务器权威的架构：模拟内核独立且确定，玩家界面和 MCP 走同一个操作接口。

```
浏览器客户端（PixiJS 渲染 + 界面）    MCP 客户端（外部 AI）
              │                            │
              └──────────┬─────────────────┘
                         ▼
          统一操作接口（校验预算/人手、写操作日志）
                         ▼
          模拟内核（纯 TS、固定步长、带种子随机数、确定性）
                         ▼
          存档 = 种子 + 操作日志 + 定期快照 → 回放 / 纪录片
AI 网关在服务器端：生成请求统一经过它，密钥不进客户端；AI 不决定任何结果。
```

- **网页优先**：浏览器打开就能玩，不用安装；之后可以打包成桌面应用。
- **模拟内核独立**：固定步长、结果确定，与画面完全分离。同一份内核可以跑在服务器上，也可以跑在浏览器里用于单人离线。
- **服务器权威**：多人时模拟跑在服务器上（家里那台就够），客户端只负责渲染和发送操作。
- **存档即回放**：随机种子、操作日志和定期快照，回放和纪录片都建在它上面。
- **内容即数据**：部件、性状、现有技术条目、疾病、委托模板都写成数据文件，方便用 Claude Code 批量生成和校验。
- **统一操作接口**：界面和 MCP 调用同一套操作，保证 AI 没有额外权限。
- **AI 网关**：生成请求统一经过服务器，密钥不进客户端。

开发方式：本文档可以导出成 Markdown 放进代码仓库，作为 Claude Code 的需求说明。

## 迭代计划

代码交给 AI 写，每个阶段的开发压到几天；大部分时间留给试玩、找人一起玩和调平衡。每个阶段有一条关卡标准，过了才往下走。

（原文此处为各阶段开发与试玩时长估计图：每阶段开发约几天，试玩与调平衡占大头。）

| 阶段 | 做什么 | 关卡标准 |
| --- | --- | --- |
| 0 · 灰盒推演 | 一片草原、3 至 4 个预设物种、种群曲线，只用灰色方块 | 自己看得停不下来 |
| 1 · 野猫与鸟岛 | 第一个情景、兽医工具、个体视图（捕捉、检查、尸检） | 没人解释，试玩的人也能玩懂 |
| 2 · 档案馆与引种 | 现有技术库约 40 条、引种、历史卡、第二三个情景 | 引种能引出有趣的连锁反应 |
| 3 · 设计台与专利 | 自己设计物种、申请书与审查意见 | AI 找捷径和批量推演都找不到主导策略 |
| 4 · 扩展与美术 | 情景库扩充、纪录片、替换美术；节奏（自动暂停）与信息呈现 | 试玩的人愿意自己再玩一遍 |

之后的阶段：多人模式、家庭委托（个体尺度）、需求系统、MCP 接入。

### 节奏说明
