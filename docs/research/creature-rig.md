# 纸偶生物：拆分、骨骼、动作、零件库，以及形状和能力怎么挂钩

调研日期：2026-10-22。用途：M0 · V3 参数化生物原型的方案。只是讨论材料，标成"需要你定"的地方定了以后再写进 GDD 和 DECISIONS。

> **来源说明**：这一份没有逐条打开原文核对，出处凭记忆，标 **未核对**。用到具体数字时，先核对、再写进 `MODEL.md`。
> 和速度、骨骼有关的已核对数字，见 `VIABILITY.md` 第三节第 1、7 项。

## 一、起点

- **剪纸方向**里的动物本来就是黄铜两脚钉固定的纸偶（P7）。真实的纸偶就是绕钉子转的，所以"拆开、绕钉子转"既是技术方案，也是风格本身。
  这在 2D 动画里叫切片骨骼（cutout）：每个零件挂在一根骨头上，骨头绕关节转，零件跟着转。
- 已经定下的约束：
  - 生物外观由"模板 + 部件"参数化拼装，体重和体重分配驱动比例，动作程序化复用（`DECISIONS.md` 2026-10-19）；
  - 塑形 a + b：功能来自体重分配，**外观层不影响能力**（2026-10-15）；
  - 复杂度预算：每样东西最多影响 3 个指标；
  - 铁律：能力只由性状推导，模拟确定，内容即数据。

## 二、骨架与零件

**骨架模板**按身体构型分，不按物种分：

| 模板 | 骨头 | 用于 |
| --- | --- | --- |
| 四足兽 | 臀（根）→ 腰 → 胸 → 颈 → 头 → 下颌；前腿、后腿各 3 节；尾 3–6 节 | 猫、兔、鼠、以后的大多数兽 |
| 鸟 | 身体（根）→ 颈 → 头 → 上下喙；腿 4 节；收起的翅膀、展开的翅膀两节；尾羽 | 鸻、以后的鸟 |
| 以后 | 两足兽（要尾巴配重）、无腿（蛇形，一串节）…… | 有需要再加 |

- **零件**是一张透明 PNG，带转轴位置（在零件自己坐标里）。零件挂在骨头上，骨头在模板里有默认长度。
- **远侧的腿和耳朵**复用近侧那张，调暗约 15%，画在身体后面。素材少一半，两侧也不会画得不一样。
- **画的先后顺序**：远侧腿 → 尾 → 身体 → 头 → 近侧腿。翻转朝向时，整组镜像。
- **每个能动的关节都是一颗铆钉**，看得见：这是纸偶的规矩，也是素材的验收标准（`handoff/006` 列出了每只动物全部关节）。
- **对位**：Lovart 不会让零件比例和参照完全一致。所以每只动物的骨架（零件转轴、骨头长度、画序）写成一份 JSON，
  第一次由我对着第一行"拼好的参照"手工校一遍；铆钉只当提示，不靠颜色自动识别（橘猫的毛色、巢的树枝和铜色太近）。
  切图用 `slice_sheet.py --parts`：整张表同一个缩放倍数，manifest 记下每个零件在原图里的位置，方便对位。
- **尾巴、长脖子**：一节节的零件够用；要更顺的弯，可以把整条尾巴做成一张沿曲线弯的贴图（PixiJS 的 `MeshRope`）。

## 三、动作：够用就好

这不是近距离的动作游戏，零件主要是为**设计**和**动物的参数**服务的。动作只要让人一眼看出"它在干什么、身体是什么样"，不追求细腻。

- **只做几种状态**：站、走、跑（兔是跳）、吃、趴 / 睡，鸟另加起飞。
  每种状态是一组关键角度（数据），走、跑在两三个关键姿态之间循环，状态之间插值过渡。
- **同一套关键姿态复用到所有身体**：角度写在骨架模板上，不写在物种上。换了零件、换了体重，照样能用。
- **走跑的快慢跟腿长**：步频按腿长缩放（动力相似，Alexander & Jayes 1983，**未核对**），放大成老虎的猫自然走得沉一些。
  这是一行公式，不是一套系统。
- **一点点跟随**：尾巴、耳朵晚半拍摆动（简单的弹簧），纸偶的味道就出来了。
- **不做**：反向运动学（IK）、脚掌贴地、物理布娃娃、逐只手做的动画。现场里动物只有几十像素高，看不出来。
  以后纪录片要近景、真觉得脚打滑难看，再加两段 IK（几十行）。
- **只在渲染层**：动作代码在 `src/proto/`（以后 `src/render/`），不进 `src/sim`，不影响确定性。推演只告诉画面"它在走 / 跑 / 吃 / 睡"。

**身体随姿态的挤压和拉伸**：它不是真的纸艺，所以纸片可以微微变形。
- 躯干、颈、尾做成可以弯曲和伸缩的贴图（PixiJS 的 `MeshPlane` / `MeshRope`，顶点很少）。
- 每个关键姿态除了关节角度，再带两三个形变数：
  - 脊背弯多少（趴、蜷是弓起来，跑是前后伸展）；
  - 躯干压扁多少（趴着时矮而宽，站着时恢复）；
  - 肚子垂多少（坐着时往下）。
- 形变幅度有上限（大约 ±15%），纸纹不至于看得出拉坏；更大的变化（比如蜷成一团睡）就整片换成那个姿态的躯干素材，以后需要时再出。

## 四、零件库：丰富，但不是画图软件

三层，越往下越少：

1. **骨架模板**（四足兽、鸟……）：决定有哪些骨头。
2. **部件**：每个槽位几种**离散的剪影**，对应 `parts.json` 里已经有的部件：
   - 嘴：啮齿门齿、研磨臼齿、裂齿、杂食齿、尖吻、四种喙；
   - 腿：步行、奔跑长腿、攀爬钩爪、掘土爪、短腿、翅膀；
   - 尾：短尾、长平衡尾、储脂尾、蓬松大尾；
   - 体表：短毛、厚绒毛、羽毛。
   每个部件一张（或几张）零件素材，转轴位置统一，所以能互换。
3. **少量形状参数**：每个部件最多两个（长短、粗细）。
   - 在一定范围内（大约 ±30%）拉伸同一张纸，纸纹的变形还看不出来；
   - 超出范围就换下一档素材（比如"短腿 / 普通 / 长腿"三档）。

**比例跟着功能走，大部分不用玩家动手**：
- 体重：按异速生长缩放。骨头粗细比长度长得快一点；大动物站得更直，抵消一部分。
- 体重分配：骨头多腿就粗，肌肉多大腿和肩就厚，脂肪多肚子就圆。
- 部件：自带的比例，比如奔跑长腿更长、掘土爪的前掌更宽。

**颜色和花纹**：零件库的素材用中性浅色纸（像 P8 叶片那样去色），颜色、花纹（虎斑、斑点、黑白花）由代码叠上去。
否则零件数要乘以花色数。现在这四种动物先用彩色的成品零件（`handoff/006`），零件库以后另出。

## 五、交互：像捏纸偶，不像建模

玩家能做的事，分三层：

1. **默认全自动**：选部件卡、设体重，形状自己出来（和仔数的"自动"一样）。大多数玩家停在这一层就够了。
2. **在动物身上拖手柄**（可选）：设计台的侧面大图上，只有几个手柄，比如腿长、尾长、耳朵、头的大小。
   - 每个手柄有范围、有档位，不能拖出离谱的形状；
   - 拖动时，画面上立刻出现后果：重心点和前后脚之间的支撑区、"和赤狐差不多快"、能量线变长或变短、老同事的批注；
   - 记的是"比自动多多少"（和 `litterBias` 一样）。体重变了，比例跟着变，偏好保留。
3. **"像谁"**：从一条现有技术开始（已经有了），再往另一条现有技术那边拉一点，比如"猫，往赤狐那边 30%"。这正好接上专利检索：越像现有技术，越可能被驳回。

**不做**：自由画轮廓、自由加骨头、数值表格、顶点编辑。

**预览**：设计台上的动物在原地慢慢走两步、停下吃一口，够看出身体比例就行。重心不稳的画成前倾（只是画面，后果在推演里）。

## 六、形状要不要影响能力（需要你定）

**现在的规则**（2026-10-15）：外观层不影响能力；能力来自体重、部件、体重分配。
按这条规则，第五节的手柄只改外观，后果在画面上看得见，在推演里没有。

**提议**：把一两个形状参数从"外观"改成"性状"，最先考虑腿长和尾长。

条件：
- 写在设计里（design schema），长度是数据，**不从素材的像素量出来**（换了美术不能改变玩法）；
- 推导走引擎，进可行性登记表，阈值带依据等级；
- 每个参数最多影响 3 个指标；
- 17 条现有技术和 `npm run routes` 的结果不变。

可以算、而且有依据的（只用闭式估算，**不做物理引擎**）：

| 形状 / 份额 | 推导量 | 依据 | 进推演的哪里 |
| --- | --- | --- | --- |
| 腿长（相对） | 步长、最高速度 | 弗劳德数（Alexander & Jayes 1983，未核对）；Hirt 2017 速度曲线（已核对） | 追捕、逃跑 |
| 腿长（相对） | 移动的能量 | 腿越长，每走一米越省（Pontzer 2007，未核对） | 能量 |
| 腿长（相对） | 骨的安全系数 | 腿越长，力臂越长，骨头受力越大（Biewener 1989 的站姿思路） | 骨骼检查（已有） |
| 尾长 | 平衡、急转 | 重心前后位置；跑动中用尾巴转向（猎豹等，未核对） | 平衡检查（新）、追捕 |
| 肌肉份额（已有） | 加速、最高速度 | 加速时间限制了大动物的最高速度（Hirt 2017） | 追捕、逃跑、能量 |
| 骨骼份额（已有） | 安全系数 | 已实现（`MODEL.md` 五之十三） | 跑不动、走不动、骨折 |

**力的平衡**（是否要算）：只需要一个静力检查，不需要模拟受力。
- 每个零件有质量：骨骼、肌肉份额分到四肢，消化道、脂肪分到躯干，头按体重的比例给；
- 由此算出重心，看重心是不是落在前后脚之间、离边缘还有多少余量；
- 前倾得厉害 → "站不稳"，像骨骼检查一样按程度影响奔跑；两足的身体要靠尾巴配重。
- 这一项只有引入了会改变重心的形状参数（长颈、大头、长尾）才有意义，所以和上面的提议一起定。

**能耗**：设计台的能量线已经按野外代谢率算了日常开销，里面已经含了平均的移动（`MODEL.md` 五之十二）。
形状只改**相对于同体重、同部件的现有技术多花或少花多少**，所以 17 条现有技术不变。

## 七、V3 原型的步骤

1. **猫**：零件到了以后切图、手工校骨架 JSON，在独立的原型页（`creature.html`）里站、走、跑、吃、趴。
   零件到之前，先用代码画的占位零件把骨架和关键姿态跑通。
2. **兔、鼠、鸟**：同一套代码，换骨架模板和关键姿态。兔跳、鸟起飞。
3. **按体重缩放**：猫放大到老虎的体重，比例按异速生长自动变；看它好不好看、动作是不是沉。
4. **怪组合**：钩喙 + 掘土爪 + 蓬松大尾，测零件互换和转轴对位。
5. **手柄和读数**：腿长、尾长两个手柄，显示重心、支撑区、按第六节估算的速度（只读，不进推演）。
6. **接进现场**：替换剪纸 demo 里的 P7 整只。

每一步都给你看截图或在线页面；第 5 步的读数，就是第六节"要不要进推演"的试玩依据。

## 八、需要你定的事

1. **形状进不进推演**：建议先只让**腿长、尾长**两项进推演（第六节的表），其余（耳、头、颈、颌）先只是外观。
   定了的话，在 `DECISIONS.md` 里改"塑形 a + b"那一行。
2. **交互层次**：默认全自动 + 可选拖手柄 + "像谁"，三层都要，还是先只做前两层？
3. **零件库素材**：现在的四种动物用彩色成品零件；零件库用中性纸 + 代码上色（建议）。
4. **骨架模板的范围**：M1 只做四足兽和鸟，两足、无腿以后再说（建议）。
