# 参数化身体：几个骨架大类 + 一整套连续参数（提案）

日期：2026-10-25，2026-10-26 按用户的回答改。状态：**方向已定，细节边做边试**（用户的回答见第九节；`DECISIONS.md`"参数化身体"）。
前情：`creature-rig.md`（骨架、零件、动作）、`DECISIONS.md`"纸偶的部件抽象""外观参数"。
出处凭记忆的标 **未核对**；用到具体数字时先核对、再写进 `MODEL.md`。

## 一、要解决的问题

用户的要求（2026-10-25）：

- 只有几个大类（四足、鸟……），其余**全部**通过参数调出来，像捏脸系统。
- 不是一个物种一套参数，而是一整套参数，所有物种共用。
- 不要"猫耳朵、狗耳朵、兔耳朵"这样一种耳朵一个选项，那等于一个物种一个特例。
- 尽量用连续变量：圆到尖是一个量，立起来还是耷拉是一个量，长短是一个量，位置是一个量。
  猫头鹰那样"看不见的耳朵"，也只是位置和尺寸取了某个值。
- 关键是两件事：
  - 对已知物种特征的覆盖要全；
  - 参数的抽象程度、可调的粒度要合适。
- 这也符合现实：很多动物之间的差异，就是某个功能为了适应新环境，往一个方向走到了极端（进化或退化），于是成了新的形态。

现在的做法离这个还差两步：

- **画面**：零件已经属于部件、不属于物种（猫的零件贴骨头拼出兔和鼠）；但耳朵的形状只能把猫耳拉长、拉宽，圆耳、垂耳、没有耳朵都做不出来。
- **推演**：每个槽位是几张离散的部件卡（9 种口器、6 种腿、4 种尾、3 种体表），效果写在卡上。

## 二、原则

1. **大类只按骨架分**。大类决定有哪些骨头、哪些插口、用哪套缩放公式（兽和鸟的寿命、繁殖不同）：
   - 现在做：四足兽、鸟；
   - **下一个：两足**（袋鼠、跳鼠、恐龙；用户 2026-10-26 定）。等四足兽、鸟的参数跑通以后再开始，不提前搭骨架；
   - 以后有需要再加：翼手（蝙蝠）、蛇形、鳍。

   大类以下没有"物种模板"这一层。
2. **一套参数，人人共用**：
   - 参数名是几何量或物理量：长度、宽度、圆尖、软硬、位置、数量。
   - "兔耳""猫耳"不是选项，是参数空间里的两个点（预设）。
   - 鸟和兽共用能共用的参数（颈长、腿长、尾长、眼、颜色）。
3. **能连续就连续**。只有自然界本来就离散的才用离散量：
   - 角有几只；
   - 有没有角质喙；
   - 第几节开始分叉。
4. **零点是"同体重、同大类的一般样子"**：
   - 记的是偏离，和 `litterBias`、`shape.leg` 一样，长度类用对数；
   - 体重变了，比例跟着缩放律变，玩家的偏好保留；
   - 不写某个参数就等于 0，所以老设计不用改。
5. **范围覆盖已知的极端**：
   - 每个参数的两端各对得上一种真实动物（第四节）；
   - 超出真实范围的部分不让拖，或者进可行性检查（和骨骼、繁殖一样）。
6. **粒度**：一个参数要在画面上看得出差别，而且不和别的参数重复表达同一件事。每个身体区域 3–7 个参数。
7. **推演只认参数，而且慢慢来**（铁律 4、5）：
   - 参数一开始只是画面；有依据了，再"升级"进推演，一次升一个，推导写进 `MODEL.md`；
   - 每个参数最多影响 3 个指标（GDD 的复杂度预算）。
8. **部件卡变成预设，不推倒重来**：
   - 现有的部件（啮齿门齿、跳跃后腿……）是参数空间里的命名点；
   - 17 条现有技术是 17 个参数向量；
   - 迁移的每一步，17 条现有技术的编译结果逐位不变（第七节）。

**进化的直觉**（用户的观察，也是这套参数最好的讲法）：每个参数是一条"适应的轴"，特化的动物就是在某条轴上走到了头。

| 轴 | 走到头的样子 |
| --- | --- |
| 耳长（散热、听） | 耳廓狐、长耳大野兔 |
| 吻长（够得着蚁穴） | 食蚁兽 |
| 前后腿比例（起跳、加速） | 跳兔、袋鼠 |
| 颊齿从切到磨（吃草） | 马、牛 |
| 远端的腿节变长、只用趾尖着地（跑） | 鹿、马 |
| 毛变硬（防身） | 刺猬、豪猪 |

设计台可以把这一点说出来，例如："你在这条轴上已经超过了耳廓狐"。

## 三、参数总表

记法：
- **L** 对数偏离：相对同体重、同大类的一般值；
- **U** 0–1 的程度；
- **P** 位置（沿一条路径的 0–1）；
- **N** 离散的数；
- **★** 已经进推演；**☆** 推演候选（第五节）；其余只是画面。

id 用英文（代码标识符），名字和说明用中文。

**"没有"怎么记**：对数偏离取不到 0，可是耳、毛、眼、颈、翼、尾羽、角都有"完全没有"的真实动物。这几个参数（下面表里一端写着"0"的）统一这样处理：
- 参数仍然是对数偏离，但有一个下限 `min`（暂定 −3，约为一般值的 5%）；
- 拖到下限就是"没有"：画面上不画这片零件（耳只剩耳孔、毛是裸皮），推演里这一项按 0 算；
- 下限以上一点点就是"很小"，和"没有"在滑块上是连着的，不是另一个开关。

`horn.count`、`beak.on` 这类本来就离散的，仍然用 N。

- **猫头鹰**："看不见的耳朵"是 `ear.length = 0`、`ear.pos` 在两侧，耳孔藏在面盘的羽毛下面。
  - 角鸮头上的"耳朵"其实是羽簇，不是耳朵，用 F 节的冠羽（`crest`）放在两侧去做。
  - 面盘本身是这套参数还没有的东西（第四节缺口）。
- **人**：中等长、圆、两侧、贴着头。
- **大象**：很宽、两侧、偏软（不完全立），扇动用耳朵的链做。

**颜色在现实里有什么用**（用户 2026-10-26 问；出处都**未核对**）：
- **藏起来**，这是最主要的用处：
  - 和背景一样：沙漠里的动物多是沙色，雪地里的白；
  - 背深腹浅（反荫蔽）：阳光从上面照，背深腹浅正好抵消肚子下的阴影，侧面看起来是平的（Thayer）；
  - 打散轮廓：斑和纹让轮廓不连续，难认出是一只动物；
  - 换季换毛：白鼬（就是游戏里的 stoat）、雪兔、雷鸟冬天变白；雪化早了，白的反而显眼（Mills 等 2013，雪兔）；
  - **藏给谁看**：猎物的眼睛大多分不清红和绿，所以虎的橘色在鹿眼里接近绿色，一样是保护色（Fennell 等 2019）。
- **给别人看**：
  - 警告色：臭鼬、蜜獾的黑白是在说"别惹我"，前提是它真的不好惹；
  - 求偶：孔雀的尾、山魈的脸；
  - 认同类。
- **热和磨损**：
  - 深色吸收的阳光多，但隔着一层毛，热量多半在毛的表面就散掉了，所以深色毛在风里不一定更热（Walsberg 1983）；
  - 黑色素让羽毛更耐磨，所以很多白色的鸟翼尖是黑的（Burtt 1986）；
  - 葛洛格法则：温暖潮湿的地方，同一类动物颜色更深。
- **没有用处的**：暹罗猫的深色末端，是色素酶怕热的副产品（上面 `pattern.points`）。
- **说不清的**：斑马的条纹，假说很多，目前证据最多的是让吸血的马蝇落不下来（Caro 等 2019）。

**对这个游戏最有意思的一点**：鸮鹦鹉是绿色的，遇到危险就一动不动，靠伪装。对付的是新西兰原来那些**靠眼睛**捕猎的猛禽（例如哈斯特鹰），很管用；
对付后来引进的白鼬、猫、鼠（**靠鼻子**找猎物），毫无用处。所以"伪装"不能是颜色自带的效果，而是推出来的：
猎物的颜色和背景像不像（猎物的性状） × 捕食者靠不靠眼睛（捕食者的性状）。这正好符合铁律 5。

现在进推演的有四样：体重、体重分配、腿长、尾长。部件卡的效果也在推演里，但它们是离散的。

**伪装要新的推演结构**，不是升级一个参数就行：
- 现在推演里的"发现"只有两处：捕食者每天仔细搜过的面积（走过的路 × 发现半径 × 成功率，`physiology.ts`），和窝被发现的概率（随掩护降低）；
- 伪装要乘在发现半径上，而且要先给捕食者加"靠什么找猎物"（眼、鼻）这个性状，给每块栖息地加"背景是什么颜色"；
- 所以排在最后，等前面几项做完再说。

**只是画面**：耳的圆尖和软硬，鬃，冠羽，胡须，尾的卷和姿态；颜色和花纹在伪装做进去以前也只是画面。
- 耳的软硬对听力有一点影响，太细，不做。

**升级的做法**（一次一个参数，每一步都守住 17 条现有技术逐位不变）：
1. 把那张卡的效果改写成这个参数的连续函数；
2. 在卡对应的参数值上，函数**正好**等于原来的数（锚点：端点直接返回原值，不做浮点插值）；
3. 卡之间按对数插值；有文献公式的用公式，再用这些锚点核对；
4. 写进 `MODEL.md`，测试守住锚点；
5. **同时把它画出来**（用户 2026-10-26 的要求）：一个参数进了推演，画面上就要看得出它，玩家才能把"它变了"和"结果变了"连起来。例如：
   - 毛长：轮廓的毛边从光滑到蓬松连续变化（毛边的起伏和长短跟着毛长），纸面上的毛流笔触变长变密；底绒厚了，轮廓整体往外胀一点；
   - 耳的面积：耳本身；
   - 远端和着地方式：脚掌、跖骨的长短，着地时是整个脚掌还是趾尖；
   - 牙和喙：张嘴时看得到的牙形、喙的轮廓；
   - 爪：脚尖的爪长和弯。

## 六、怎么画（技术上最大的风险）

切图零件其实已经是矢量（用户 2026-10-26 指出）：`vector.json` 里每片零件是一条轮廓多边形 + 几块色区多边形（条纹、浅色），纸纹是平铺的贴图；
贴骨头（`fit.ts` 的 `boneWarp`、`regionStretch`）就是在多边形上做参数化的变形。所以要分的不是"切图 ↔ 程序生成"，而是**多边形从哪里来**：

| 多边形从哪里来 | 用在哪 | 好处 | 问题 |
| --- | --- | --- | --- |
| **描出来的多边形 + 参数化的变形算子**（现在的贴骨头就是） | 原画里有的部位：躯干、腿节、头、耳、吻、尾 | 保留手绘的起伏，和原画一个味道 | 算子要做得够多：拉长、拉宽之外，还要磨圆尖端、折弯、垂下、加毛边 |
| 几张基零件之间混合 | — | 仍然是画出来的 | 每个参数要两端的素材、顶点一一对应，素材会爆炸。**不用** |
| **按参数凭空生成** | 原画里没有的种类：角、刺、冠羽、鬃、蹄、喉囊 | 什么值都画得出来 | 要调得好看；风格靠同一条上色管线 |

**建议：能从描出来的多边形变过去，就变过去；变不出来的种类才凭空生成。**
- 两种多边形走同一条上色管线（`cutout.ts` 的 Shape：轮廓 + 色区 → 纸纹、白边、阴影、铆钉），所以是一个风格。
- 变形算子是这套参数在画面上的落点：一个参数 = 一个（或几个）算子的强度。例如耳尖圆尖 = 把耳尖附近的轮廓按曲率磨圆，耳软硬 = 沿耳的中线折弯。
- **毛边**也是算子：沿轮廓往外加起伏，幅度和长短随毛长连续变化（第五节第 5 步）。
  `handoff/007` 的 B2（三种体表的边）因此不再做成三版零件，只当作校准毛边算子的参考：短毛、厚绒毛两端的样子要像它。羽毛的羽片边属于鸟大类，仍然是另一种边。
- **花纹**用程序生成：噪声加阈值，斑和纹由噪声拉伸的方向来控制。

**例子：耳朵**
- 轮廓：从猫耳描出来的多边形出发。长、宽沿耳的中线拉（现在已经有）；圆尖用"磨尖端"算子：耳尖附近的点往一条圆弧上收，程度就是 `ear.tip`，往尖的方向则把耳尖附近收窄；内耳的色区跟着同一个变换走。
- 软硬：耳朵是两节的链，复用 `tail.ts`。软骨越软，肌肉抵消的重力越少，耳朵在重力下垂下来；在哪一节折下来，也由软硬定（半立的柯利犬耳）。
- 位置：头片上的耳插口，沿颅骨轮廓按位置参数滑动。
- 耳长 0：只剩一个耳孔，不画耳片。

**降低风险**：
- 先做耳朵原型（圆 ↔ 尖、立 ↔ 垂、看不见的耳朵），看变形以后的耳朵和身体其他零件放在一起像不像同一套纸偶；再做喙。
- 可以请 Lovart 出"形状参考表"：同一只耳朵从圆到尖、从立到垂排一行，用来校算子的曲线，不直接用作零件。

## 七、迁移：不推倒重来

1. **设计里加 `morph`**：
   - 参数向量，全部可选，不写就是 0（一般样子）；
   - `appearance.earLen`、`earWide` 并进 `morph.ear.length`、`morph.ear.width`（换成对数：`length = ln(earLen)`）；
   - 现在 schema 里 `earLen` 最小是 0.3（`design.ts`），并进来时要放宽到"没有"（见第三节的下限），否则拼不出鼹鼠、猫头鹰；
   - schema 带范围校验。
2. **部件卡 = 预设**：
   - 每张卡写上它对应的参数值（数据，`parts.json` 加 `morph` 字段）；
   - 选卡就是把这些参数一次设好；
   - 设计里仍然记着部件，推演照旧读部件的效果；morph 先只管画面，所以 17 条现有技术逐位不变。
   - **滑块离开了卡的预设值怎么办**：这时画面变了，推演读的还是卡，两者会对不上（耳朵拖到很长，推演里散热不变）。规则：
     - 还没升级进推演的参数（只是画面），随便拖，卡不变；
     - 已经升级进推演的参数，推演读的就是参数本身，不再读卡，也就不存在对不上；
     - 处在中间（卡的效果还在推演里、这个参数还没升级）的参数，滑块锁在卡的预设值上，旁边写"这条轴的效果还由'某某卡'决定，换卡来调"。

     这样任何时候，画面上看到的和推演算的都是同一个身体。
3. **一次升级一个参数进推演**（第五节的做法）。
   全部升级完以后，部件卡只剩"预设"的意思；推演只读参数。
4. **画面**：
   - 先做耳朵、喙的变形算子（第六节的原型）；
   - 再做毛边算子（接第五节的毛长）；
   - 再做凭空生成的角、刺，和花纹；
   - 再把腿的远端、着地方式接进贴骨头。
5. **设计台**：
   - 卡片（预设）→ 每个区域的滑块 → 在纸偶身上拖手柄（`creature-rig.md` 第五节的三层）；
   - "像谁"变成两个参数向量之间插值；
   - 相似度检索（新颖性审查）改成参数空间里的距离。

## 八、对玩法的影响

- **进展**：GDD 说部件"从少量开始，随委托和发明逐步变多"。改成**解锁轴和范围**：
  - 新的一条轴是一项发明（第一次让耳朵能垂下来）；
  - 把范围放宽是一次改进（耳更长）。

  数据上仍然是一项一项的。
- **审查和检索**：参数空间的距离天然就是"像不像现有技术"。想法池里的几项直接可做：
  - "两种现有技术之间渐变混合"；
  - "反向设计谜题：拼出一只真的穿山甲"。
- **讲进化**：滑块拖到头就是特化，设计台能告诉你"你已经比耳廓狐还极端"。课程里的适应、趋同（刺猬和豪猪各自长出刺）有地方落脚。
- **仍然不做**（`creature-rig.md` 第五节）：自由画轮廓、自由加骨头、顶点编辑。参数再多，也是捏纸偶，不是画图软件。

## 九、用户的回答（2026-10-26）

1. **大类**：下一个是两足。等四足兽、鸟跑通以后再做（第二节）。
2. **参数表的粒度**：初步可以，要边做边试、不断调整。
3. **进推演的顺序**：照建议（体表保温 → 耳的散热 → 腿的远端和着地 → 牙和喙 → 爪）。
   另外，每一项都要在画面上看得出来，例如毛的长短要体现在轮廓和纹理线条上（第五节第 5 步）。
4. **画法**：切图零件本来就是矢量轮廓，所以改成"描出来的多边形 + 变形算子，变不出来的才凭空生成"（第六节）。
5. **颜色和花纹**：用户问颜色在现实里有什么用，回答在第三节 J。**待定**，建议：
   - 现在仍然只是画面；
   - 伪装作为最后一个推演候选（要新的推演结构，见第五节）；
   - 颜色深浅吸热，效应小，先不做。
