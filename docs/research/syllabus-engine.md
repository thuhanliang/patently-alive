# 课本进引擎：Edexcel IAL 生物 U2、U4 的生态和兽医知识怎么变成推演规则

2026-11-27 用户：要把 U2、U4 里生态相关的知识都放进推演引擎，书上的知识、甚至题目里的例子（比如生物多样性指数），要能在游戏里复现出来。

原则不变（DECISIONS 2026-10-24"课程融入"）：**课本就是规则，不是课件**。
- 先体验，后命名。
- 公式在卡片背面，想看才翻。
- 不弹窗，不出题。

这份文档只多做一件事：每条知识都对应引擎里的一段规则，再配一个**能复现的例子**。课本或真题里的数，喂进引擎，要算出同样的答案。这些例子都写成回归测试（`tests/syllabus/`），引擎改了，课本例题必须照样对。

## 一、三种"进引擎"的方式

1. **计量**（`src/sim/measure/`）：课本里的指数和计算，比如多样性指数、杂合度指数、样方盖度、能量传递效率。
   - 按铁律 4，指标只由引擎定义：游戏里所有这类数字都从这里算，界面只负责显示。
   - 输入是玩家**亲手采到的样本**（样方、捕捉、血样、粪样），不是上帝视角的真值。
   - 所以玩家算出来的数会有抽样误差。这本身就是课本内容（4C.2"什么时候测""测几次"）。
2. **机制**（推演本身）：课本里讲"为什么"的部分，变成推演的规则。比如：
   - 能量沿食物链逐级减少；
   - 突变和选择改变等位基因频率；
   - 建立者效应、瓶颈；
   - 病原体传播，免疫和疫苗；
   - 抗生素选出耐药。
   课本的结论不写进代码，而是由规则自己跑出来。测试检查跑出来的方向和量级对不对，例如"瓶颈以后杂合度下降"。
3. **工具**（兽医和野外的操作）：课本里的实验方法，变成玩家手里的工具，结果从推演的真实状态里读出来。
   - 野外：样方、样带、标志重捕；
   - 化验：McMaster 虫卵计数、血涂片、PCR 和电泳；
   - 尸检：死亡时间。

## 三、要补的三块推演

### 1. 等位基因（基因库）

- 每个物种带几个基因座：
  - 几个中性的（相当于微卫星，用来做 DNA 图谱、亲缘、杂合度）；
  - 一个免疫相关的（相当于 MHC，影响得病后的结局）。
- **格子里按等位基因频率记，个体展开时按频率抽基因型；收拢时把基因型加回频率**。按铁律 2 必须守恒。
- 出生时按亲代频率抽，抽样用带种子的随机数，所以小种群会漂变。投放时，建立者的基因型从"品系"里抽：
  - 档案馆的现有技术来自大种群，杂合度高；
  - 事务所设计的品系只有几只亲本，杂合度低，是真实的瓶颈。
- 现有技术的数据加 `genetics`：每个基因座几个等位基因、频率多少。没有文献数据的标【未核对】。

### 2. 病原体（疾病与寄生虫）

- **病原体是数据**（`src/data/pathogens/*.json`，用 schema 校验）。每种病原体写清楚：
  - 类型：病毒、细菌、原虫、蠕虫、外寄生虫；
  - 宿主，以及各宿主的易感程度；
  - 传播：接触（随密度）、粪口（格子里的虫卵量）、媒介（湿地里的蚊子）；
  - 潜伏期、病程、致死率、对体况的影响；
  - 康复以后的免疫和消退；
  - 能用什么查：粪检虫卵、血涂片、PCR 的带；
  - 体征：发烧、消瘦、贫血（黏膜苍白）、羽毛蓬乱、流涎。
- 推演里，每个物种、每个年龄段、每一格，分成易感、感染、康复三份计数（蠕虫按虫负荷分档），个体展开时每只带自己的状态。
- 宿主的性状只走推导（铁律 5）：
  - 密度、家域重叠决定接触；
  - 免疫基因座决定结局；
  - 体况差的更容易死。
  不在设计台上写"抗病"。

### 3. 尸体和时间

- 死亡记下时刻、地点、死因（死因账本已有）。
- 尸体在格子里留几天：
  - 体温按冷却曲线下降；
  - 尸僵先出现、再消退；
  - 苍蝇按温度产卵、蛆按积温长大。
- 尸检时读这些，推断死了多久。
