# 阶段 2：档案馆与引种

## 目标

打开第二个身份"引种者"：玩家可以从自然档案馆里挑真实物种引进情景，用天敌、竞争者去解决问题，并承担引进以后收不回来的后果。
本阶段要做：现有技术库（约 40 条）、档案馆检索、引种操作、档案馆的历史卡，以及第二、第三个情景。

## 关卡标准

**引种能引出有趣的连锁反应。** 过了才进入阶段 3（设计台与专利）。

这里的"有趣"有两层意思：
- 后果看得懂：引进的物种吃了谁、挤走了谁、自己怎么样了，能从死因、尸检和曲线里读出来；
- 后果是真实生态史那样的：会出乎玩家意料，但事后觉得"本该想到"。

## 范围

做：

1. **现有技术条目**：每一条都是一个能推演的真实物种。数值沿用阶段 1 的物种 schema，另加档案信息：
   - 档案信息包括分类、知识卡和出处；
   - 知识卡每条 2–4 句真实知识，开发时从维基百科（CC BY-SA，要署名）或维基数据起草，带出处，**由你审核**；
   - 数值先用仓库里已有的 PanTHERIA、AnAge，没有的项写明估计依据；
   - `npm run data:check` 要覆盖全部条目；
   - 鸟类缺数据库数值（体重、窝卵数、食性等）时，再开一个 handoff，请你在本地下载 EltonTraits / AVONET。
   - 首批约 40 条，只收推演引擎算得了的：陆生哺乳动物和地面活动的鸟。第一批 10 条左右，要覆盖鸟岛控鼠的候选（獴、白鼬、雪貂、伶鼬等）。
2. **档案馆界面**：
   - 按名字或性状检索。
   - 查不到时按性状相似度给出最接近的条目，回复"暂无收录，最接近的现有技术是……"，结果确定、可复现。
   - 每条显示数据档案和知识卡，并附上**按性状推导**的"在这个情景里它可能吃谁、谁会吃它"。这一项由引擎的捕食规则算出，不由数据声明（铁律 5）：查"谁能吃船鼠"时，雏鸟和蛋也会一起出现在名单上。
3. **引种操作**：新操作 `introduce`，照样走 `Session.submit`（铁律 7）。
   - 玩家选条目、数量、性别和年龄、投放地点。
   - 花费来自数据：购买、运输、检疫的预算，加上人手和时间。
   - **不可撤销**：投放后只能靠兽医工具和生态手段减少。
   - 投放的个体从个体进入格子，数量、年龄结构守恒（铁律 2）。
   - 业主规定（如"本岛禁止引入哺乳动物"）写在情景数据里，由操作接口校验，属于世界内的理由。
4. **鸟岛的引种者阶段**：GDD 情景走法第 4 步。
   - 鸟岛开放引种。
   - 选獴时附上夏威夷獴的历史卡：獴控鼠本身不差，问题是它离开农田，去吃地面筑巢的鸟。
   - 档案条目可以带自己的历史卡，在相关时刻出现。
5. **引擎补课**：
   - **人类用地**：农田（甘蔗田）这种地形，给鼠提供食物，人在其中活动。
   - **栖息地偏好**：动物在哪里觅食、扩散到哪里，由食物和掩护推导，不靠手写"待在田里"。
   - **阶段 1 遗留**：兔子啃不薄灌丛（见 `MODEL.md` 已知问题）。情景 3 的转折依赖这一条，先修好。
   - 每加一样新机制，先说清楚三件事：影响哪些指标、玩家在哪里看得见它、它会让人怎么失败（GDD 复杂度预算）。
6. **情景 2 · 甘蔗田的獴**：取材夏威夷 1883 年引入獴。
   - 地图：甘蔗田、低地、山林。
   - 委托：控制田里的鼠害；本地有地面筑巢的鸟，比如夏威夷黑雁 nēnē。
   - 转折：獴把鼠压下去了，但它不待在田里，跑进林子吃鸟和蛋。
   - 加一个情景选择菜单，并定出解锁规则（比如完成鸟岛后开放引种者情景）。
7. **情景 3 · 兔子、猫与苔原**：取材澳大利亚麦夸里岛。
   - 物种：兔、猫、在地洞里繁殖的海鸟、草丛植被。
   - 转折：清除猫以后兔子回升，植被被啃光，海鸟失去营巢地。
   - 黏液瘤病毒属于疾病（阶段 4），这里**只写进历史卡**，不建模。开局设在病毒效力减退、兔子已经开始回升以后。
8. **批量推演找主导策略**：
   - 每个情景 × 每个可引进的条目（再加几种数量和地点）批量跑，记录评分。
   - 如果某次引种在几个情景里几乎都是最优，就算漏洞，按平衡原则补上真实代价，不加禁令。
   - 沿用 `npm run routes` 的做法：脚本玩家只通过 `Session.submit` 下操作。
9. **美术（本阶段这部分）**：
   - 新物种先用代码画的田野笔记占位（主色平涂加墨线），主色写进配色表。
   - 农田、山林的地形着色由我做。
   - 新物种的精灵等 `handoff/002` 的四种动物定下画法后，再开一个 handoff 分批请你生成。

不做：
- 设计台、专利和审查意见（阶段 3）。
- 疾病、疫苗、驱虫、TNR（阶段 4）。
- **节奏（自动暂停）和信息呈现的改造（阶段 4）**：本阶段新增的信息尽量放进已有的面板或按需打开的地方，不新增常驻面板。
- 纪录片、多人、AI、MCP。

## 建议顺序（每步一个 PR）

1. 现有技术条目：schema、第一批 10 条左右、`data:check` 覆盖条目
2. 档案馆界面：检索、最接近条目、按性状推导的"可能吃谁 / 谁会吃它"
3. 引种操作：`introduce`、花费、不可撤销、业主规定
4. 鸟岛开放引种、獴的历史卡
5. 引擎补课：兔子啃薄植被；农田地形与栖息地偏好
6. 情景 2 · 甘蔗田的獴；情景选择菜单与解锁
7. 情景 3 · 兔子、猫与苔原
8. 条目补到约 40，知识卡交你审核
9. 批量推演找主导策略、调平衡
10. 发 Pages 版本（阶段末，等试玩判断）
